## 1. 제품 정의

### 한 줄 설명

**Nook은 정리되지 않은 생각을 대화로 풀어놓으면, 지금 고민하는 질문과 그 질문이 바뀐 흐름을 정리해 남기는 서비스다.**

### 사용자 약속

사용자는 처음부터 질문을 잘 정리할 필요가 없다. Nook은 답을 대신 정하거나 사용자를
분석하지 않는다. 사용자가 말한 내용 안에서 현재 중요한 질문을 함께 좁히고, 실제로
생각의 중심이 바뀐 경우에만 그 이동을 기록한다.

### 핵심 문구

> **복잡한 생각, 말하면서 정리해요.**

첫 화면은 다음 행동을 쉽게 만드는 데 집중한다.

> **머릿속에 걸리는 게 있나요?**
>
> 정리되지 않아도 괜찮아요. 생각나는 대로 적어보세요.

## 2. 문제와 사용자

### 문제

개인적인 고민과 선택은 정보 부족만으로 해결되지 않는다. 사용자는 이미 검색하거나
누군가와 이야기했어도 다음 상태에 머물 수 있다.

- 생각은 많지만 무엇이 중요한지 모르겠다.
- 여러 고민이 섞여 어디서부터 말해야 할지 어렵다.
- 같은 생각을 반복하며 현재 질문을 놓친다.
- 대화 중 관점이 바뀌어도 무엇이 계기였는지 남지 않는다.
- 조언보다 자신의 생각을 정리하는 과정이 필요하다.

기존 채팅은 대화 로그를 남기지만, **현재 질문과 질문이 이동한 이유**를 다시 쓰기 좋은
구조로 남기지는 않는다.

### 타깃 사용자

정답이 정해지지 않은 진로·관계·소비·학업·생활 선택을 혼자 반복해서 생각하거나,
메모·지인·범용 AI로 풀어본 사용자. 특정 주제나 심리 상태로 한정하지 않는다.

### 핵심 사용자 과업

> 생각을 완성된 질문으로 만들기 전에 말하기 시작하고, 대화가 끝났을 때 지금 무엇을 더
> 생각해야 하는지 확인한 뒤, 필요하면 그 지점에서 다시 이어가고 싶다.

## 3. 제공 가치

| 순간 | 사용자가 얻는 가치 |
| --- | --- |
| 시작 | 정리해서 설명하지 않고도 말할 수 있다. |
| 대화 | 생각이 옆으로 새도 현재 질문을 놓치지 않는다. |
| 종료 | 결론이 없어도 다음에 생각할 지점이 남는다. |
| 재방문 | 지난번 맥락을 처음부터 설명하지 않고 이어간다. |

Nook의 최소 성공은 사용자가 정답을 얻는 것이 아니다.

> “그냥 계속 마음에 걸린다”에서 “내가 지금 더 생각해야 할 건 이것이다”로 이동하는 것.

## 4. 제품 원칙

1. **답보다 질문을 정리한다.** 판단과 결정은 사용자에게 남긴다.
2. **사용자가 말한 것만 다룬다.** 숨은 원인·성향·진단을 만들어내지 않는다.
3. **질문 이동을 보수적으로 기록한다.** 새로운 내용이 아니라 중심 질문이 실제로
   바뀌었는지를 본다.
4. **확정권은 사용자에게 있다.** AI가 제안한 질문은 사용자가 확인하거나 수정해야
   기록이 된다.
5. **흐름을 끊지 않는다.** 애매한 판정을 버튼으로 떠넘기지 않고 한 번 더 자연스럽게
   묻는다.
6. **쌓인 양을 평가하지 않는다.** 진행률·생각 깊이·성장 점수를 만들지 않는다.
7. **종료와 보관을 분리한다.** 대화를 마쳤다고 자동으로 저장하지 않는다.
8. **안전과 사용자 종료 의사를 우선한다.** 더 묻는 것보다 멈추는 것이 먼저다.

품질의 기준은 통찰의 개수가 아니다.

> **사용자가 실제로 이동한 생각만 붙잡고, 사용자가 하지 않은 해석은 만들지 않는 것.**

## 5. 핵심 개념

| 개념 | 의미 | 화면에서의 역할 |
| --- | --- | --- |
| 중심 질문 | 지금 대화에서 보고 있는 질문 | 현재 대화와 지도의 기준 |
| 질문 이동 | 대화 중 해결하고 싶은 중심이 달라짐 | 사용자가 승인하면 새 노드로 기록 |
| 분명해진 것 | 질문은 같지만 조건·생각이 구체화됨 | 노드 사이의 보조 기록 |
| 곁가지 질문 | 현재 흐름과 구분되는 별도 질문 | 지나가거나 새 대화로 시작 가능 |
| 생각의 흐름 | 질문과 이동 근거가 이어진 기록 | 진행률이 아닌 사고의 흔적 |

질문 이동이 한 번도 없는 세션도 정상이다. 변화가 없으면 UI가 억지로 변화를 만들지
않는다.

## 6. 핵심 경험

### 6.1 시작

1. 사용자가 정리되지 않은 생각을 적는다.
2. Nook이 안전 여부와 입력 성격을 확인한다.
3. 여러 고민이 섞여 있으면 무엇부터 볼지 한 번만 묻는다.
4. 중심 질문을 제안한다.
5. 사용자가 질문을 수정하거나 확정한다.
6. 같은 화면에서 대화가 열리고 Nook이 먼저 되묻는다.

정보 조회·비교·직접 실행으로 풀리는 요청은 억지로 고민 탐색으로 바꾸지 않는다.

### 6.2 대화

- 현재 질문을 기준으로 한 번에 하나씩 묻는다.
- 질문이 유지되면 같은 흐름에서 더 분명하게 만든다.
- 질문의 중심이 바뀌면 새 질문을 제안하고 사용자 확인을 받는다.
- 사용자가 직전 질문의 전제를 정정하면 그 전제를 폐기하고 중심 질문으로 돌아간다.
- 다른 질문이 생기면 현재 흐름을 막지 않고 곁가지로 분리한다.
- 사용자가 원하면 곁가지 질문에서 새 대화를 시작할 수 있다.

새 대화를 시작해도 원래 대화는 자동 종료되지 않는다. 연결된 세션은 출처만 공유하고
종료·보관 여부는 각각 결정한다.

### 6.3 종료와 나가기

Nook이 현재 정도에서 정리해도 좋다고 판단하면 다음을 제안한다.

- 남기고 마치기
- 더 생각하기

사용자는 언제든 직접 나갈 수 있다.

- 남기고 나가기
- 남기지 않고 나가기
- 대화로 돌아가기

서버에 확정된 정보까지만 보관한다. 입력창에만 적힌 내용이나 도착하지 않은 응답은
저장하지 않는다.

## 7. 화면과 기록 구조

### 홈

- 새 생각 입력이 가장 큰 행동이다.
- 최근 보관 이야기와 이어갈 대화를 함께 보여준다.
- 미리보기로 실제 사용 뒤의 기록 구조를 먼저 확인할 수 있다.

### 대화

- 대화와 현재 질문 지도를 함께 보여준다.
- 노드를 선택하면 해당 질문이 시작된 메시지로 이동하고, 다시 선택하면 현재 위치로
  돌아온다.
- 질문 확인 화면과 대화 화면은 같은 구조를 사용해 전환 단계를 만들지 않는다.

### 생각 더미

생각 더미는 기록의 상태를 세 공간으로 구분한다.

| 공간 | 의미 |
| --- | --- |
| 내 서랍 | 사용자가 명시적으로 남긴 이야기 |
| 이어갈 대화 | 아직 종료·보관 결정을 하지 않은 대화 |
| 휴지통 | 삭제했거나 남기지 않은 계정 사용자의 기록 |

곁가지 질문만 따로 모으는 목록은 두지 않는다. 곁가지에서 실제 대화를 시작하면 하나의
새 세션이 되어 위 상태 중 하나에 놓인다.

### 내 서랍과 이야기 상세

- 이야기 한 개를 책 한 권으로 표현한다.
- 한 페이지에 20권을 보여준다: 데스크톱 10×2, 모바일 5×4.
- 책을 가리키거나 키보드로 선택하면 같은 책이 정면으로 나온다.
- 사용자는 책 순서를 바꿀 수 있다.
- 상세에서는 대화 원문, 중심 질문, 지나온 질문, 분명해진 것과 연결 출처를 함께 본다.
- 질문·구간 목차, 카드 넘김, 키보드와 스와이프 탐색을 제공한다.

### 미리보기

처음 쓰기 전에 홈·대화·생각 더미·이어갈 대화의 모습을 표본 데이터로 확인하는 읽기
전용 모드다.

- 실제 컴포넌트에 고정 표본을 주입한다.
- 저장·모델 호출·DB 변경은 하지 않는다.
- 실제 기록과 섞이지 않도록 미리보기 상태를 계속 표시한다.
- 표본에서 실제 대화를 시작하는 진입점을 제공한다.

## 8. 보관 정책

### 상태 원칙

- 대화 완료와 기록 보관은 서로 다른 결정이다.
- 연결된 대화도 각각 보관하거나 버릴 수 있다.
- 질문 노드는 지나온 역사로 유지하고, 현재 설명은 수정할 수 있다.

### 기간

| 대상 | 정책 |
| --- | --- |
| 계정 사용자의 진행 중 대화 | 24시간 동안 이어갈 대화에 노출 후 휴지통 이동 |
| 휴지통 | 이동 후 7일 동안 복원 가능, 이후 삭제 |
| 내 서랍 | 사용자가 삭제하거나 탈퇴하기 전까지 보관 |
| 익명 기록 | 장기 보관을 보장하지 않음 |

첫 입력이 서버에 저장된 순간부터 이어갈 대화가 생긴다. 첫 질문을 확정하기 전에 나간
경우도 복귀 대상이다.

## 9. 계정과 개인정보

### 로그인 시점

로그인을 생각 입력 전의 필수 절차로 두지 않는다. 비로그인 사용자는 첫 중심 질문을
확인하고 그 질문 안에서 대화해 본 뒤, 다음 질문으로 이동하거나 기록을 남길 때 계정을
연결한다.

### 계정 연결

- 익명 사용자 ID에 OAuth identity를 연결한다.
- 이메일 문자열을 비교해 계정을 임의 병합하지 않는다.
- 로그인 뒤 원래 화면과 보관 선택을 유지한다.
- Google과 Kakao 로그인을 제공한다.

### 동의와 삭제

- 연령 확인·이용약관·개인정보처리방침을 항목별로 동의받는다.
- 동의 버전과 시점을 기록하고 중대한 변경에는 재동의를 받는다.
- 탈퇴하면 계정과 개인 데이터를 즉시 삭제한다.
- 동일 로그인 수단의 재가입은 30일 제한하며, 원문 식별자 대신 HMAC digest만 남긴다.

## 10. Safety와 제품 경계

Nook은 감정을 진단하거나 치료하는 서비스가 아니다. 사용자가 직접 말한 감정은 생각을
이해하는 재료로만 다룬다.

위험 신호는 일반 대화보다 먼저 검사한다.

- **STOP:** 일반 질문과 기록 생성을 중단하고 필요한 안전 안내를 제공한다.
- **HANDOFF:** Nook의 질문보다 외부 도움이 적절한 경우 안내 후 일반 대화를 종료한다.

위험 원문 저장, 분류 기준과 안내 계약은 [`RULES.md`](RULES.md)를 따른다.

## 11. 핵심 가설과 지표

| 가설 | 확인 지표 |
| --- | --- |
| 사용자는 정리되지 않은 상태로 시작한다. | 서술형·혼합형 입력 비율, 첫 질문 재구성 비율 |
| 질문을 좁히는 과정이 생각 정리에 도움이 된다. | 종료 설문 `정리됐어요` 비율, 완료율 |
| AI 제안이 사용자 생각과 크게 어긋나지 않는다. | 첫 질문·질문 이동 승인/수정/거절률 |
| 구조화된 기록이 다시 생각할 이유가 된다. | 복귀율, 이야기 재열람률, 곁가지 재시작률, 7일 재방문율 |

초기 문제 가설의 방향 판단 기준은 소규모 테스트 10명 중 6명 이상이 다음 문항에
`정리됐어요`로 응답하는 것이다.

> **대화를 마치고, 지금 무엇을 더 생각해봐야 할지 정리됐나요?**

작은 표본의 방향 확인용 기준이며 제품 성과를 확정하는 KPI로 해석하지 않는다.

## 12. MVP 범위

### 포함

- 자유 입력에서 첫 중심 질문 제안·수정·확정
- 질문 중심 대화와 분명해진 것 기록
- 질문 이동 판정·승인과 생각의 흐름
- 곁가지 질문과 연결된 새 대화
- 종료·나가기·중간 이탈 복귀
- 내 서랍·이어갈 대화·휴지통·복원
- 책장 정렬·페이징과 이야기 상세 탐색
- 익명 체험, OAuth 연결, 닉네임, 동의·탈퇴
- Safety Gate와 요청량·중복 처리 제한
- 읽기 전용 미리보기

### 제외

- 심리 진단·감정 점수·AI의 최종 결정
- 반복 질문 자동 탐지와 여러 세션의 Question Graph
- 공개·소셜·사용자 간 질문 공유·사람 매칭
- 태그·검색·카테고리 자동 분류
- 스트릭·성장 점수·달력
- 이메일 로그인

## 13. 차별화

“AI가 질문한다”거나 “고민을 대화로 정리한다”는 기능 자체를 차별점으로 주장하지 않는다.
범용 AI에서도 사용자가 프롬프트를 잘 쓰면 비슷한 대화를 만들 수 있다.

Nook의 차이는 다음 경험을 **기본 흐름과 데이터 구조**로 제공하는 데 있다.

1. 완성된 질문이 아닌 정리되지 않은 입력에서 시작한다.
2. 현재 질문을 기준으로 대화를 이어간다.
3. 질문이 실제로 바뀐 경우에만 사용자 확인 후 기록한다.
4. 다른 질문은 현재 흐름을 방해하지 않고 분리한다.
5. 채팅 로그가 아니라 질문의 흐름을 다시 이어가기 좋은 형태로 남긴다.

## 15. 확장 방향

MVP는 한 세션 안의 생각의 흐름을 다룬다. 실제 재방문 가치가 확인된 뒤에만 다음을
검토한다.

1. 여러 세션에서 반복되는 질문 연결
2. 과거와 현재의 질문 비교
3. 필요한 시점에 과거 질문 다시 꺼내기
4. 장기 개인 질문 아카이브와 내보내기

수익화는 Freemium + Subscription을 가설로 두되, 핵심 정리 경험은 무료 범위에서 막지
않는다. 가격과 유료 기능은 기록이 충분히 쌓여 재방문 가치가 확인된 뒤 결정한다.
