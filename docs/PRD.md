## 0. 정의

### 서비스명

**Nook** — 구석진 아늑한 자리, 뭔가를 잠시 넣어두는 공간.

> **Nook**
> 답을 주는 대신, 내가 어떤 질문을 지나왔는지.

이름이 의미를 전부 짊어지지 않는다. 태그라인이 채운다.

### 제품 카테고리

AI 저널도, AI 상담도, AI 마인드맵도 아니다. 
**Personal Thinking Tool** — 대화를 통해 내 생각의 현재 위치를 찾고, 그 이동 경로를 남기는 개인 사고 도구.

### 사용자에게 보이는 언어

> 무슨 생각 하고 있었어요?
> 두서없어도 괜찮아요. 편하게 들려주세요.

첫 화면에서 "답을 주지 않습니다"라고 선언하지 않는다. 사용자는 "내 질문이 흐릿하다"고 생각하며 들어오지 않는다. "이거 어떡하지" 상태로 들어와서, 나갈 때 **"아, 내가 사실 이걸 고민하고 있었구나"**를 체감한다.

## 1. 문제

### 출발점

정보가 부족해서 생기는 문제가 아니다. 오히려 **정보가 너무 많아서** 생긴다. 검색하면 수십 개 의견이 나오고 AI에 물으면 또 하나의 답이 나오는데, 그럴수록 "그래서 나는 뭘 원하는데"가 흐려진다.

### 두 가지 페인포인트

**말하는 것 자체가 버겁다.** 정리하러 왔는데 상황을 처음부터 설명하고 논리적으로 정리해서 말해야 한다.

**대화할수록 생각의 경로를 잃는다.** 어디서 시작했는지, 왜 지금 이야기로 넘어왔는지, 지금 실제로 뭘 묻고 있는지가 흐려진다. 대화 로그는 남지만 **생각이 어떻게 이동했는지는 남지 않는다.**

### 내부 문제 정의

> 답을 찾지 못하는 문제가 아니라, **생각이 진행되면서 내 질문의 중심을 잃어버리는 문제.**

## 2. 시장과 경쟁

**사람이 AI에게 개인적 고민을 말하는 행동은 이미 존재한다.** 새 행동을 만드는 게 아니라 이미 일어나는 행동에서 **휘발되는 부분을 잡는다.** 인접 시장에 유료 수요도 있다(Rosebud 월 $12.99, Mindsera 월 $14.99, Day One Gold 연 $74.99).

| 영역 | 대표 | 하는 일 | Nook과 다른 점 |
|---|---|---|---|
| 범용 AI | ChatGPT | 질문·조언·개인적 대화 | 대화가 기본 객체. Nook은 **질문의 이동 경로**가 기본 객체 |
| AI 저널 | Rosebud, Mindsera, Reflect, Day One | 기록 → 분석 → 통찰 | 사람을 분석. Nook은 **경로를 남김** |
| AI 마인드맵 | Xmind AI, Mapify | 아이디어를 확장·구조화 | 더 펼치는 게 강점. Nook은 **수렴** |
| 멘탈웰니스 | Wysa | 정서 지원, CBT, 임상 근거 | 치료 목적. Nook은 **비임상 생각 정리** |

**주의**

- "AI가 질문해준다"는 차별점이 아니다. Rosebud의 Dig Deeper가 이미 한다. 차이는 **질문의 목적**이다.
- "대화를 시각화한다"도 차별점이 아니다. 차이는 **방향**이다.
- 멘탈헬스와는 의도적으로 거리를 둔다. 붙는 순간 임상 근거·위기 대응·전문가 검증이라는 다른 경기장이 열린다.

### 가장 강한 대비

> **마인드맵은 생각을 펼친다. Nook은 생각의 중심을 찾는다.**

## 4. 세션 흐름

| # | 단계 | 내용 |
|---|---|---|
| 1 | Raw Thought | 정리되지 않은 생각 그대로 입력. 예시 칩으로도 시작 |
| 2 | Start Reframe | AI가 시작 질문 제안 → 사용자 확정 → **Node 0** |
| 3 | Reflection | 한 번에 하나씩 되물음 |
| 4 | Judge | 무슨 일이 일어났는지 판정 |
| 5 | Shift Proposal | 중심이 바뀌었을 때만 새 질문 + 근거 제안 |
| 6 | User Confirm | 맞음 / 수정 → 확정된 것만 지도에 저장 |
| 7 | Thought Map | 중심 경로, 한 구간 최대 4노드 |
| 8 | Closure | 결과 화면 + 보관 여부 1회 선택 |

### 첫 화면

```text
무슨 생각 하고 있었어요?
두서없어도 괜찮아요. 편하게 들려주세요

[                        ]

이직하고 싶은데 이유를 모르겠어
계속 만나는 게 맞는지 모르겠어
사고 싶은데 계속 망설여져
그냥 머릿속이 복잡해
───────────────────────────
지나온 생각          최근 2~3개
9월 9일
이직할까? → 지금 회사에서 원하는 성장이 가능한가?
                          [전체 보기]
───────────────────────────
남겨둔 질문 3개        [열어보기]
```

**예시 칩은 데모 모드가 아니다.** 누르면 그 문장이 실제 Raw Thought가 되어 일반 입력과 같은 흐름을 탄다. 심사용 체험과 실제 서비스를 따로 만들지 않는다.

카테고리를 분산한다. 관계 예시만 크게 두면 연애상담 앱으로 인식된다. **칩 문장은 실제로 Shift가 잘 일어나는지 사전 검증한다.**

**`지나온 생각`을 첫 화면 주인공으로 만들지 않는다.** 내부 보관 개념인 생각더미를 홈에서는 `지나온 생각`으로 표시한다. 신규 사용자는 입력창만 보이고, 쓸수록 아래가 채워진다.

## 5. 대화 엔진

### 5.1 실행 순서

```text
0. Safety Gate            ← Moderation + 별도 Safety Classifier
1. Explicit User Control  ← 코드
2. Structural Check       ← 코드, 숫자만 셈
3. Turn Judge             ← LLM (Prompt B)
4. Reframe / Reflection   ← LLM (Prompt C 또는 D)
5. 사용자 선택
```

**1~2는 결정론적이다.** 0은 Moderation 신호와 별도 Safety Classifier로 일반 Judge와 분리하고, 3~4만 Core LLM 단계로 둔다. Safety classifier는 `label/category`만 출력하며 행동과 연락처는 결정론적 매핑이 정한다.

**Safety는 Judge 안에 넣지 않는다.** Safety Gate가 대화 엔진 앞에 있다는 원칙이 깨지고, Judge 역할이 다시 넓어진다.

**Structural Check를 Judge에서 뺀 이유:** LLM에게 "노드가 4개인지 세어봐"를 시킬 이유가 없다. 코드가 먼저 확인하고 걸리면 Judge를 호출하지 않는다.

**Explicit User Control이 코드인 이유:** "그만할래"에 Judge를 태우면 못 알아들을 위험만 생긴다.

### 5.2 Shift 판정

**핵심 기준**

> 새로운 이야기가 나왔는가가 아니라, **기존 질문에 답해도 핵심 고민이 더 이상 해결되지 않는 상태인가.**

**Shift는 "처음 질문이 가짜였다"가 아니다.** 대화를 진행하면서 **사용자가 지금 풀고 싶은 중심 질문이 달라진 것**이다. 처음 질문이 완전히 정상이어도 이동할 수 있다. "숨겨진 진짜 고민"으로 설명하면 제품이 심리 발굴 쪽으로 기운다.

**실전 체크**

- 새 질문에 답한 뒤 **원래 질문으로 돌아가야 하는가** → 하위 질문 / Branch
- 새 질문 때문에 **원래 질문 자체를 다르게 보게 되는가** → Shift 후보
- 그 이동을 **사용자가 실제 발화에서 반복·강조했는가** → YES여야 Main Path

**내부 4문**

```text
Q1. 기존 질문의 세부조건·증거·정보를 확인하는 중인가?     YES → NOT SHIFT
Q2. 기존 질문에 답해도 새 고민이 남아 있는가?            NO  → NOT SHIFT
Q3. 질문의 대상·기준·레벨 중 하나 이상이 달라졌는가?      NO  → NOT SHIFT
Q4. AI가 먼저 연 방향이 아니라 사용자가 자발적으로 꺼냈나?  NO  → MEDIUM 이하
                                                     YES → Shift 후보
```

**Q4가 게이트다.** Q1~Q3가 맞아도 사용자가 실제로 이동하지 않았다면 Shift가 아니다. AI가 먼저 연 방향에 대한 동의는 자발적 증거로 세지 않는다. 자발성·완화형 화자 보정·1턴 자기 선언 예외·최근 창 밖 MEDIUM carryover의 정확한 실행 규칙은 [`docs/RULES.md`](RULES.md)를 따른다.

엔진은 `현재 문장 판정기`가 아니라 **최근 생각 흐름 판정기**다.

### 5.3 참조 예시

**SHIFT**

| 시작 | 이동 후 |
|---|---|
| 이직할까? | 나는 회사를 떠나고 싶은 걸까, 성장하고 싶은 걸까? |
| 이 관계를 계속할까? | 나는 이 사람이 변하기를 기다리고 있는 걸까? |
| 노트북을 살까? | 필요한 건 성능일까, 좋은 장비를 갖는 만족감일까? |
| 친구에게 서운하다고 말할까? | 원하는 건 사과일까, 중요하게 여겨진다는 확인일까? |
| 대학원을 갈까? | 공부를 더 하고 싶은 걸까, 진로를 미루고 싶은 걸까? |
| 독립할까? | 원하는 게 공간일까, 내 삶을 내가 결정한다는 느낌일까? |

**NOT SHIFT**

| 시작 | 나온 질문 |
|---|---|
| 이직할까? | 연봉이 얼마 이상이면 옮길까? / 통근시간은? |
| 노트북을 살까? | RAM 16GB면 충분할까? |
| 이 관계를 계속할까? | 지난달에도 같은 일이 있었나? |
| 독립할까? | 월세 80만원을 감당할 수 있을까? |

> 질문이 더 구체적이 됐다고 새 노드를 만들면 안 된다.

**AMBIGUOUS** — 문장만으로는 판정 불가, 최근 흐름을 봐야 함

- 이직할까? → 지금 회사에서 성장할 수 있을까?
- 계속 만날까? → 내가 받은 상처를 아직 못 넘긴 걸까?
- 노트북을 살까? → 나는 왜 비싼 물건 살 때 불안하지?
- 퇴사할까? → 일을 쉬고 싶은 걸까?
- 헤어질까? → 내가 외로운 게 두려운 걸까?

**"밖 → 안" 이동은 판정 기준이 아니다.** Shift에서 자주 관찰되지만, 기준으로 쓰면 모든 고민을 내면 탐색으로 끌고 간다.

### 5.4 Confidence 정책

| Confidence | Judge action | 동작 |
|---|---|---|
| HIGH | `SHIFT` | Shift 제안 (Prompt C 호출) |
| MEDIUM | `REFLECT` | 사용자가 흘린 표현을 포함한 질문으로 확인 |
| LOW | `REFLECT` | 현재 질문 안에서 계속 좁힘 |

**CHECK 액션은 사용하지 않는다.** MEDIUM 상황은 선택 버튼으로 사용자에게 판정을 넘기지 않고, Prompt D의 질문으로 자연스럽게 확인한다.

**보수 정책**

> False Negative는 허용하고 False Positive Shift를 강하게 줄인다.

**오류 치명도 순서**

1. NOT SHIFT를 SHIFT로 판정 ← 가장 큰 오류
2. MEDIUM이어야 하는데 HIGH
3. 실제 SHIFT를 늦게 잡거나 놓침

### 5.5 Reframe

요약이 아니라 재정의다.

| | 예 |
|---|---|
| 요약 (X) | 상대의 변화에 대해 이야기했어요 |
| 재정의 (O) | 나는 상대가 변하기를 기다리고 있는 걸까? |

**허용 경계**

> **사용자가 여러 번 말한 것을 하나로 묶는 것은 허용.**
> **사용자가 말하지 않은 원인·성향·심리적 해석을 추가하는 것은 금지.**

- "지금은 잘해준다" + "앞으로 달라질 것 같다" + "기다려보고 싶다" → "나는 상대가 변하기를 기다리고 있는 걸까?" **허용**
- "내가 너무 예민한 걸까?" → "나는 내 감정을 신뢰하지 못하는 걸까?" **금지**

이 경계가 없으면 "심리 원인 발굴 금지" 원칙이 Reframe 자체를 죽인다.

**근거 제시 의무.** 새 노드를 제안할 때 왜 그렇게 봤는지를 한 줄로 함께 낸다.

### 5.6 이 규칙은 모든 문구에 적용된다

Node 생성뿐 아니라 Closure, Clarification, Shift 근거, 종료 화면, 안내 문구, Safety 문구까지 전부.

> **서비스는 관찰된 것 이상을 말하지 않는다.**

- "지금 질문이 처음보다 달라졌어요" → 화면에 근거가 있으므로 **허용**
- "여기서 멈추면 나중에 더 잘 보일 거예요" → 보장할 수 없는 효과, **금지**
- "이건 고민할 일이 아니에요" → 사용자의 고민 가치를 평가, **금지**
- "드시고 싶으면 드세요" → 답을 대신 내림, **금지**

### 5.7 Branch

Shift는 아니지만 나중에 Nook에서 독립적으로 생각해볼 가치가 있는 질문이면 Branch 후보로 잡는다.

**정보 조회만으로 해결되는 곁가지 질문은 Branch 후보로 저장하지 않는다.**

Branch 후보는 대화 중 `PENDING` 상태로만 임시 저장한다. 실시간으로 내용을 펼쳐 대화를 방해하지 않고, 정상 종료 화면에서 한꺼번에 보여준다.

> **발견과 보관은 별개다. 사용자가 명시적으로 고른 질문만 남는다.**

- 사용자가 고른 후보 → `KEPT`, `남겨둔 질문`에 표시
- 고르지 않은 후보 → 종료 결정과 같은 트랜잭션에서 hard delete
- 세션 기록을 생각더미에 남길지와 Branch 질문을 남길지는 서로 독립된 선택
- Branch 질문을 만든 턴에도 일반 대화는 계속
- 보관한 질문과 같은 방향이 HIGH Shift가 되면 중심 질문으로 승격 가능

평가 계약 v4.1의 `input.pile` / `promote_pile_item` 필드명은 fixture 호환을 위해 유지한다. 제품 DB 엔티티 이름은 `Branch Question`이며 Pile Item 테이블이나 `RESUMED` 상태를 따로 만들지 않는다.

---

## 6. 단순 질문 처리 (CLEAR_AS_IS)

Prompt A는 모든 입력을 Reframe하지 않는다. 출력은 세 가지다.

| 의미 | 조건 |
|---|---|
| `NEEDS_INFO` | 외부 사실·조회·비교 또는 직접 실행으로 바로 풀림 |
| `CLEAR_AS_IS` | 질문이 이미 분명하고 정리되지 않은 갈등이 없음 |
| `REFRAME_NEEDED` | 정보만으로 풀리지 않고 현재 질문이 아직 흐림 |

판정 순서는 `NEEDS_INFO → CLEAR_AS_IS → REFRAME_NEEDED`로 고정한다.

**CLEAR_AS_IS 예:** "오늘 치킨 먹을까?" / "지금 커피 마실까?" / "지금 음악 들을까?"

이 경우 억지로 이동시키지 않는다. 억지 Reframe은 우리가 금지한 거의 모든 걸 위반한다 — 사용자가 안 한 말을 만들고, 심리 원인을 발굴하고, Depth Guard를 넘는다.

```text
지금 질문은 이미 분명해 보여요.
`오늘 치킨을 먹을까?`

[여기까지 정리하기]  [조금 더 생각해보기]
```

**단, 표면의 가벼움으로 판단하지 않는다.** 판단 기준은 **사용자 발화 자체에 아직 정리되지 않은 갈등이 있는가**다.

- "오늘 치킨 먹을까?" → CLEAR_AS_IS
- "요즘 자꾸 시켜 먹는데 이래도 되나" → REFRAME_NEEDED
- "치킨 먹을까 말까 30분째 고민 중" → REFRAME_NEEDED

## 7. Depth Guard

자기이해가 결과로 생기는 건 괜찮다. 자기분석을 목적으로 대화를 끌고 가지 않는다.

**허용 범위:** 행동/선택 → 원하는 것 → 우선순위 → 현재의 기대·전제

**AI가 먼저 열지 않는 영역:** 애착유형, 트라우마, 어린 시절, 결핍, 무의식, 성격 진단, "나는 왜 이런 사람인가"

> **자기이해를 만들기 위해 깊게 파지 않는다. 생각을 선명하게 하다 보니 자기이해가 생길 수는 있다.**

## 8. Safety Flow

되묻는 것이 메커니즘인 서비스라 위험이 구조적으로 있다. **대화 엔진과 완전히 분리된 별도 게이트**로 둔다.

### 8.1 감지 — 2단계

```text
사용자 발화
  ↓
1차 Moderation API (omni-moderation-latest)
  ↓
2차 Safety Classifier (Judge와 완전히 별도)
  ↓
classifier output: label + category
  ↓
safety_mapping.json → behavior
  ↓
CONTINUE → Message 저장 + Turn Judge
HANDOFF  → Message 저장 + 되묻기 중단
STOP     → 위험 신호 발화 원문 미저장 + Safety Flow
```

**저장 순서가 중요하다.** Safety Gate와 결정론적 매핑을 먼저 통과시킨다. `STOP`이면 원문을 저장하지 않고, `HANDOFF`이면 위험 판정이 아니므로 해당 사용자 발화를 Message로 저장한 뒤 Judge 없이 종료한다.

**Moderation은 신호, 2차 분류기가 문맥을 판단한다.**

**2차 분류기는 `label + category`만 출력한다.** `behavior + contact`는 `safety_mapping.json`이 결정한다.

### 8.2 STOP / HANDOFF에서 멈추는 것

되묻기 중단 · Shift 판정 중단 · 노드 생성 중단 · 지도 갱신 중단.

**서비스의 메커니즘 자체를 끈다.** 다만 `STOP`은 위험 원문을 저장하지 않고, `HANDOFF`는 해당 Message를 저장한다.

### 8.3 문구

하지 않는 것: 진단 · 되묻기 · 상태 확인 시도 · 조언 · 평가.

```text
지금은 질문을 더 이어가지 않을게요.
바로 도움을 받을 수 있는 연락처를 안내할게요.
```

### 8.4 연락처 — 상황별로만

| 상황 | 안내 |
|---|---|
| 자살·자해 신호 | **자살예방 상담전화 109** (24시간) / 급한 상황이면 **119** |
| 청소년 맥락 | **청소년 상담전화 1388** (24시간) |
| 폭력 피해 맥락 | **여성긴급전화 1366** (24시간) |
| 일반 정신건강 | **정신건강 상담전화 1577-0199** |

전화번호를 고정 리스트로 모두 노출하지 않는다.

### 8.5 이후 흐름

**[새 생각 시작하기]** 버튼 하나. 현재 세션은 닫고 새 세션을 연다.

"다른 이야기로"라고 쓰지 않는다. 강제로 창을 닫지 않는다.

### 8.6 저장 처리

**Safety 화면에서는 아무것도 묻지 않는다.**

| 처리 | STOP | HANDOFF |
|---|---|---|
| 세션 상태 | `SAFETY_STOPPED` | `HANDOFF_STOPPED` |
| 해당 사용자 발화 | **저장하지 않음** | **Message로 저장** |
| Judge Log / Node / Clarification / Branch | 생성하지 않음 | 생성하지 않음 |
| 생각더미·남겨둔 질문 노출 | 없음 | 없음 |
| 기존 안전한 세션 데이터 | 삭제하지 않고 숨김 | 삭제하지 않고 숨김 |

`STOP`은 원문 없는 최소 Safety 메타데이터만 저장한다. `HANDOFF`는 Message와 최소 Safety 메타데이터를 저장하되 경고 톤으로 다루지 않는다.

## 9. Closure — 세 종류

### A. Soft Closure

AI가 지금 정리할 가치가 있는 지점이라고 판단해도 종료를 강제하지 않는다.

> 처음에는 **"이직할까?"** 에서 시작했고, 지금은 **"성장할 환경을 찾는 걸까?"** 까지 왔어요.
> **[여기까지 정리하기] [이 질문 조금 더 보기]**

### B. Structural Transition

노드·턴·Branch 상한 도달. **"그만하라"가 아니라 사고 단위를 나누는 것이다.**

> 여기까지 하나의 생각 흐름이 만들어졌어요. 이 질문에서 더 이어갈 수도 있어요.
> **[이 질문에서 이어가기] [여기까지 정리하기]**

**대화만 계속하고 지도를 멈추면 안 된다.**

### C. Safety Stop / Handoff

8장 참조. 이 경로에서만 일반 `조금 더 보기`와 보관 선택이 없다.

### Intentional Closure 정의

> **더 이상 질문할 수 없는 순간이 아니라, 더 질문할 수 있어도 지금 정리할 가치가 있는 순간을 알아차리는 것.**

### 종료와 보관은 다른 상태다

사용자가 `[여기까지 정리하기]`를 선택하면 먼저 `status = COMPLETED`가 된다. 이 값은 대화가 끝났다는 뜻이지, 기록이 보관됐다는 뜻이 아니다.

**1. 나중에 다시 볼 질문**

Branch 후보가 있을 때만 보여주며, 사용자가 고른 질문만 `KEPT`로 남긴다. 고르지 않은 후보는 삭제한다. 아무것도 고르지 않는 것도 정상이다.

**2. 이번 세션 기록**

```text
[이 기록 남기기]  [남기지 않고 나가기]
```

- **이 기록 남기기** → 계정이 연결된 사용자는 `storage_state = SAVED`, `생각더미`에서 질문 경로를 볼 수 있다.
- **남기지 않고 나가기** → 계정이 연결된 사용자는 `storage_state = TRASHED`, 휴지통에서 7일 동안 복원할 수 있다.
- 휴지통 문구: `휴지통으로 이동해요. 7일 안에 복원할 수 있고, 이후 영구 삭제돼요.`
- **익명 사용자의 남기지 않고 나가기** → `TRASHED`를 만들지 않고 세션을 즉시 hard delete한다. 문구는 `이 기록은 저장되지 않아요.`
- 익명 사용자가 세션 또는 Branch 질문을 하나라도 보관하면 먼저 OAuth identity를 연결한 뒤 보관 결정을 확정한다.

세션 기록과 질문 보관은 독립적이다. 세션을 남기지 않아도 사용자가 보관한 질문은 유지되고, 세션을 남겨도 고르지 않은 Branch는 유지하지 않는다. 단, 익명 사용자가 어떤 항목이든 보관하려면 계정 연결이 필요하다.

Safety STOP/HANDOFF에서는 이 선택을 묻지 않고 일반 목록에서 숨긴 뒤 임시 보존 만료 정책을 따른다.

## 10. 구간과 Anchor

사용자에게 "Map 1 / Map 2"라고 보여주지 않는다. **하나의 생각 흐름 안의 여러 구간**이다.

새 구간은 독립적인 Node 0을 만들지 않는다.

> **이전 구간의 마지막 확정 Node를 Anchor로 이어받는다.**

데이터에서는 노드를 복제하지 않고 참조한다. 구간 2를 그릴 때 첫 노드를 Anchor에서 읽어와 표시하되, **구간 2의 소유 노드로 카운트하지 않는다.**

> **지도 구간은 여러 개여도 Thought Path는 하나다.**

## 11. 시각화

### 화면 요소 다섯 개

| 요소 | 의미 | 생성 기준 |
|---|---|---|
| **Main Node** | 질문의 진전 | HIGH Shift + 사용자 승인 |
| **Clarification** | 같은 질문 안에서의 진행 | 의미 있는 범위 축소 |
| **Shift Evidence** | 왜 이동했는가 | 노드 사이 연결선에 한 번 |
| **Branch indicator** | 따라가지 않은 질문 후보 | 개수만 |
| **Current Question** | 지금 묻고 있는 것 | 항상 |

### Clarification

**Reframe 규칙 동일 적용.** 범위를 좁혀 표현하는 것은 가능, 새 의미·원인·성향 추가는 금지.

**한 Node 구간에 화면 표시 최대 2~3개. HIGH confidence만 반영.**

**Clarification은 수정될 수 있다.** 나중에 사용자 말이 바뀌면 교체하거나 제거한다.

| 성격 | 저장 | 변경 |
|---|---|---|
| Main Node | 승인된 사고의 역사 | append only |
| Clarification | 현재까지 확인된 보조 정보 | mutable |

### 절대 넣지 않는 것

- 턴마다 찍히는 점
- `1/4`, `50%`, 완성도 게이지 같은 진행률
- "생각 정리 중" 같은 가짜 진행 표시
- Branch 내용의 실시간 노출

### Shift 0 세션

Shift가 없어도 정상 결과다.

> 처음 질문은 그대로예요. **이직할까?**
> 대신 이야기하면서 몇 가지가 분명해졌어요.

### 시각화 원칙

> **노드는 질문의 이동을 보여준다.**
> **Clarification은 같은 질문 안에서 실제로 선명해진 것만 보여준다.**
> **대화량이나 시간을 진행처럼 표현하지 않는다.**
> **따라가지 않은 질문은 존재만 알리고 시야에서는 치운다.**
> **지도는 진행률이 아니라 사고의 흔적이다.**
> **아무것도 선명해지지 않은 순간에는, 아무것도 추가하지 않는 것이 정확한 시각화다.**

## 12. 생각더미

`COMPLETED + SAVED` Thought Session을 보여주는 보관 화면이다. 별도 Archive 테이블을 만들거나 같은 경로를 복제하지 않는다.

Shift가 있었던 세션은 첫 질문 → 마지막 질문을 보여준다.

Shift 0 세션은 같은 질문을 반복 표시하지 않고 질문 + 대표 Clarification을 보여준다.

**대화 전문은 기본 표시하지 않는다.** 남기려는 것은 대화 기록이 아니라 경로다.

**반복 질문 표시는 MVP에서 제외한다.**

생각더미에서 삭제를 누르면 즉시 hard delete하지 않고 휴지통으로 이동한다. 휴지통에서는 7일 안에 복원할 수 있고, 복원하면 생각더미로 돌아온다.

---

## 13. 남겨둔 질문

대화에서 발견된 모든 Branch가 아니라, **정상 종료 때 사용자가 명시적으로 보관한 질문만** 보여주는 화면이다.

**"미해결 질문"이라 부르지 않는다.** 답을 내야 하는 숙제가 아니라 사용자가 나중에 다시 보고 싶다고 고른 질문이다.

### 동작 두 개

- **여기서 시작하기** — 그 질문이 새 세션의 Raw Thought가 된다. 같은 질문에서 여러 세션을 시작할 수 있고 질문은 계속 남는다.
- **삭제** — 확인 후 즉시 영구 삭제

```text
이 질문을 삭제할까요?
삭제하면 다시 볼 수 없어요.
[취소] [삭제]
```

질문 삭제는 휴지통을 거치지 않는다. 이미 그 질문에서 시작한 세션은 유지하고 `origin_branch_id`만 `NULL`로 바꾼다.

원본 세션이 7일 뒤 영구 삭제돼도 보관한 질문은 유지한다. 이때 출처 FK만 `NULL`이 된다.

제품 DB 상태는 `PENDING / KEPT`뿐이다. `RESUMED`로 사용 완료 처리하지 않는다.

## 14. 인증

**MVP는 구글 / 카카오 소셜 로그인만.** 이메일+비밀번호는 후순위.

**로그인 시점은 첫 화면이 아니다.**

```text
익명 사용자로 세션 진행 → 지도 완성 → 종료 화면
              세션 기록 + Branch 질문 보관 선택
                         ↓
        하나라도 보관                 아무것도 보관하지 않음
      구글 / 카카오 연결               "이 기록은 저장되지 않아요"
              ↓                                 ↓
    같은 사용자 ID로 보관                     즉시 폐기
```

### Supabase Identity Linking을 사용한다

익명 사용자에게도 처음부터 user ID가 있고, 나중에 OAuth identity를 **연결**하는 구조다.

**앱에서 이메일을 비교해 계정을 임의 병합하지 않는다.**

**남기지 않고 나가는 것도 정상 경로다.** 세션 기록 선택과 Branch 질문 선택은 범위가 다르며, Branch는 사용자가 명시적으로 고른 것만 남긴다. 익명 사용자가 아무것도 보관하지 않으면 복원 불가능하므로 휴지통 안내를 하지 않고 즉시 폐기한다.

## 15. 기술 구조

**별도 백엔드 서버를 만들지 않는다.**

```text
프론트 + API   Next.js (한 프로젝트, app/api/)
배포          Vercel
DB + 인증      Supabase (PostgreSQL + Auth)
AI            OpenAI
안전 1차       OpenAI Moderation
코드          GitHub
```

**모델은 역할과 품질 관문에 따라 나눠 쓴다.**

사용 후보는 `GPT-5.6 Luna / Terra / Sol` 세 종류로 제한한다. Astra는 Nook의 비용 최적화 후보에서 제외한다.
한 모델을 모든 단계에 고정하지 않고, 동일 평가셋에서 품질 하한을 통과한 가장 저렴한 구성을 역할별로 고른다.

| 작업 | 선택 원칙 |
|---|---|
| 완화형 계산·상한·보관·매핑 | 결정론적 코드, LLM 미사용 |
| Turn Judge, Reflection, Branch/Clarification 추출 | Luna/Terra/Sol 중 Core 품질 관문을 통과한 최저 비용 구성 |
| Node 0 Reframe, Shift Reframe | Terra/Sol 중 생성 품질 관문을 통과한 구성 |
| Safety Classifier | Core와 분리 평가한 뒤 Luna/Terra/Sol 중 선택 |

상대적으로 비싼 모델을 검토할 우선순위는 **사용자의 지도에 영구히 남을 문장을 만드는 때**다.
현재 Sol 32건 결과는 Judge 프롬프트의 기준선이지 운영 모델 확정 결과가 아니다.

**비용 안전장치**

- API 키는 절대 프론트에 두지 않는다
- 선불 크레딧 소액 충전 + 자동 충전 OFF
- IP당 사용량 제한

**넣지 않는 것:** Redis, 벡터 DB, 임베딩, 별도 분석 도구, ORM, Docker, 별도 백엔드 저장소.

## 16. 데이터 구조

정확한 필드·FK·RLS·삭제 규칙은 [`docs/ERD.md`](ERD.md)를 Source of Truth로 사용한다.

### 핵심 원칙

> **대화 자체보다 질문의 이동을 중심 데이터로 저장한다.**
> **대화 종료와 기록 보관은 별도 상태다.**
> **완료·보관된 세션이 곧 생각더미 항목이다. 같은 내용을 두 번 저장하지 않는다.**
> **Node는 지나온 사고의 역사, Clarification은 현재 이해라 수정될 수 있다.**
> **구간은 여러 개여도 하나의 Thought Path로 연결한다.**
> **AI 판정 결과와 사용자에게 보여줄 기록은 분리한다.**

### 상태 두 축

| 필드 | 값 | 뜻 |
|---|---|---|
| `status` | `ACTIVE / COMPLETED / SAFETY_STOPPED / HANDOFF_STOPPED` | 대화 lifecycle |
| `storage_state` | `TEMPORARY / SAVED / TRASHED` | 보관 lifecycle |

- 정상 종료는 `COMPLETED + TEMPORARY`를 먼저 만든다.
- 계정이 연결된 사용자의 보관 선택은 `SAVED`, 남기지 않기는 `TRASHED`로 바꾼다.
- 익명 사용자가 아무것도 보관하지 않으면 `TRASHED` 없이 즉시 hard delete한다.
- 휴지통은 7일 뒤 hard delete한다.
- 진행 중 이탈 또는 보관 미결정 임시 데이터는 마지막 활동 기준 24시간 뒤 정리한다.
- HANDOFF는 직접 위험 STOP과 구분해 `HANDOFF_STOPPED`로 남기되 일반 사용자 목록에서는 숨긴다.

### 엔티티

| 엔티티 | 역할 |
|---|---|
| **Auth User** | Supabase 사용자, 익명 → identity linking |
| **Thought Session** | 한 번의 생각 흐름 + 대화/보관 상태 |
| **Segment** | 긴 세션의 구간 |
| **Message** | Safety를 통과한 실제 대화 |
| **Question Node** | 사용자 승인된 중심 질문 `START / SHIFT` |
| **Shift Edge** | 질문이 이동한 이유 |
| **Clarification** | 같은 질문 안에서 선명해진 것 |
| **Branch Question** | 발견 후보 `PENDING` 또는 보관 질문 `KEPT` |
| **Session Feedback** | 종료 설문, Session당 0~1개 |
| **Judge Log** | 검증된 판정 운영 로그 |
| **Safety Event** | 원문 없는 최소 Safety 메타데이터 |

별도 `Archive`, `Trash`, `Pile Item`, `Check Event` 테이블은 만들지 않는다.

### 데이터 계약

- 보관 질문은 원본 세션 삭제 뒤에도 소유권을 유지하도록 `user_id`를 직접 가진다.
- Question Node는 사용자 승인 이후에만 저장하며 AI 제안문과 사용자 최종문을 함께 보존한다.
- Question Node와 Shift Edge는 append-only, Clarification은 수정·무효화 가능하다.
- 새 Segment는 이전 Segment 마지막 Node를 Anchor로 참조하며 Anchor는 새 Segment `node_count`에 포함하지 않는다.
- 보관한 질문은 여러 Session의 `origin_branch_id`가 참조할 수 있다.
- 질문 삭제 시 재시작 Session은 유지하고 `origin_branch_id SET NULL`.
- 원본 Session 영구 삭제 시 보관 질문은 유지하고 출처 FK만 `SET NULL`.
- `node_count`, `turn_count`, `branch_count`는 원본 변경과 같은 트랜잭션에서 갱신한다.
- `STOP`으로 분류된 위험 신호 원문은 저장하지 않는다. `HANDOFF` 발화는 Message로 저장한다. 두 경로 모두 Moderation/Classifier 전체 입출력은 저장하지 않는다.
- RLS는 읽기뿐 아니라 다른 행을 참조하는 연결 생성까지 소유권을 검증한다.
- Judge Log는 Zod 검증을 통과한 구조화 결과만 저장하며 사용자에게 노출하지 않는다.

평가 계약 v4.1 호환을 위해 Judge 출력의 `promote_pile_item` 필드명은 그대로 둔다. 제품 DB 엔티티명과는 분리한다.

## 17. 프롬프트 네 개

### Prompt A — Start Reframe

Raw Thought → 시작 질문 또는 빠른 라우팅. 출력은 `NEEDS_INFO / CLEAR_AS_IS / REFRAME_NEEDED`.

- 사용자 발화 재료만 사용
- 없는 원인·성향 추가 금지
- 확신이 낮으면 원문에 가깝게
- 사용자 승인 전 확정하지 않음

### Prompt B — Turn Judge

입력: 현재 Main Question, 최근 3~4턴, Main Path, 현재 Branch 후보.

출력: action, branches, clarifications, confidence, evidence.

> **Judge는 문장을 만들지 않는다. 판정만 한다.**

### Prompt C — Shift Reframe

Judge가 SHIFT를 반환했을 때만 호출. 새 중심 질문 + 근거 한 줄.

### Prompt D — Reflection Generator

Judge가 REFLECT를 반환했을 때만 호출. 사용자에게 던질 실제 질문 하나를 생성.

규칙:

- 기본 출력은 질문 하나다. 별도의 되받기 문장을 반복하지 않는다
- 사용자 표현을 다음 질문 안에 자연스럽게 이어 붙인다
- 사용자 발화의 사실뿐 아니라 확신 수준도 임의로 강화하지 않는다
- 현재 Main Question을 바꾸지 않는다
- 한 번에 하나만 묻는다
- 사용자가 말하지 않은 심리 원인을 열지 않는다
- 현재 질문의 모호한 부분만 좁힌다
- 과거 질문(PAST)은 세션당 최대 1회이며, 사용 후 PRESENT 또는 COMPARE로 현재에 복귀한다

### "조금 달라요"

사용자가 직접 자유 편집한다. AI가 대안을 다시 생성하지 않는다.

## 21. 테스트셋

입고된 평가셋은 Judge 32개·Start 17개·Safety 15개다. Judge의 boundary 1개는 정답률에서 제외한다. 평가 파일과 검증 스크립트는 [PR #2](https://github.com/rudin0806/Nook/pull/2)에서 검토 중이며 아직 main 반영 전이다. Judge는 `gpt-5.6-sol` reasoning high의 strict 31/31 회귀를 통과했지만, Start·Safety의 계약 충돌과 생성 프롬프트 평가는 별도다. [문서 검증](reviews/2026-09-12-document-validation.md)과 [Judge 최종 회귀](reviews/2026-09-14-judge-sol-tuning.md)를 함께 참고하며 정적 검증·모델 fixture 결과·실사용 품질을 구분한다.

**범주:** 명확한 SHIFT · NOT SHIFT · 하위 질문 · Branch · MEDIUM 경계 · AI가 만든 자기해석 · Branch → Shift 승격 · 좋은 지점에서 Close · 피로로 Close · 반복으로 Close · Depth Guard · 외부→내부 억지 이동 · CLEAR_AS_IS · 단순해 보이지만 갈등이 있는 질문 · NEEDS_INFO.

**애매한 경계 사례가 가장 중요하다.**

| CLEAR_AS_IS | 비슷해 보이지만 갈등 있음 |
|---|---|
| 오늘 치킨 먹을까? | 요즘 커피를 줄이려는데 계속 마셔도 될까? |
| 지금 음악 들을까? | 이걸 살까 말까 일주일째 보고 있어 |
| 지금 커피 마실까? | 오늘 연락할까 말까 계속 고민 중 |

`내일 우산 가져갈까?`처럼 외부 정보 확인으로 바로 풀리는 질문은 `CLEAR_AS_IS`가 아니라 `NEEDS_INFO`로 별도 검증한다.

상단 메뉴는 `이야기 나누기 / 서랍`으로 표현한다. 서랍은 사용자가 보관한 기록을 여는 화면이다. 기존 내부 `생각더미` 및 `SAVED` 데이터 의미는 유지한다. 문서 앞부분의 `지나온 생각` 홈 표기는 이 결정으로 대체한다. 진행 중 대화는 서랍 보관과 구분한다. 크림·녹색 팔레트를 유지하고 둥근 카드, 부드러운 외부·내부 그림자로 입체감을 준다. 조작 요소의 테두리와 키보드 포커스는 유지한다.
