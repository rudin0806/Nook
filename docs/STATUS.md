## 최근 반영

- 책장의 진한 초록·회색 톤을 제거하고 페리윙클·민트·오렌지에서 분화한 8색으로
  교체했다. 홈의 작은 번호도 책별 전경색을 사용해 대비를 유지한다.
- 760px 이하 공통 셸을 다시 조정해 18px 본문 여백, 짧은 헤더, 44px 이상 터치 표적,
  한 줄 컬렉션 탭과 모바일 전용 입력·도구 줄을 적용했다.
- 홈 생각 더미의 책 색을 목록과 같은 8색 순서로 통일하고, 초록색을 덮어쓰던 예외
  규칙을 제거했다.
- 홈과 생각 더미의 제목·부제목·복귀 안내를 짧은 `해요`체로 정리해 모바일에서 긴
  안내가 두 줄로 늘어나지 않게 했다.
- 생각 더미 미리보기에 `내 서랍`·`이어갈 대화`·`휴지통` 진입점을 넣고, 홈의
  `전체 보기`가 `이어갈 대화` 표본 목록을 바로 열도록 연결했다.
- 사용자가 직전 질문의 전제를 명시적으로 정정하면 그 프레임을 폐기하고 중심 질문으로
  돌아가도록 Prompt D와 결정론적 정정 신호를 보완했다.
- 생각 더미에서 순서를 편집하는 중에도 개별 이야기를 휴지통으로 옮길 수 있게 했다.
- 이어갈 대화 수는 `3+` 같은 근삿값 대신 서버가 센 실제 숫자로 표시한다.
- 이어갈 대화 선택 삭제에서 체크박스와 제목이 겹치던 여백 우선순위를 바로잡았다.
- 책장 도구 줄은 보기 방식을 왼쪽, 순서 편집을 다른 컬렉션의 편집 동작과 같은 오른쪽
  자리에 배치하고, 운영체제 글꼴에 따라 깨지던 문자 아이콘을 SVG로 교체했다.
- 앱 심볼과 워드마크를 공통 셸에 적용했다.
- 홈의 이어갈 대화 카드가 그리드 밖으로 넘치지 않도록 카드 더미를 컨테이너 안에
  가뒀다.
- 1100px 이하에서 대화·확정·마친 이야기의 행 순서를 명시해 두 단이 한 칸에 겹치던
  문제를 해결했다.
- 760px 이하에서 홈 입력 높이와 문장 줄바꿈을 모바일 전용 값으로 분리했다.
- 모바일 마친 이야기는 결과를 먼저 읽고 대화를 이어서 읽는 순서로 정리했다.

## 핵심 기술 결정

- 사용자가 확정하기 전의 질문 후보는 Question Node로 저장하지 않는다.
- 질문 이동은 append-only 기록으로 남기고, 현재 설명은 수정 가능한 상태로 분리한다.
- Safety Gate는 일반 대화 엔진보다 먼저 실행한다.
- 모델 출력은 Zod 검증을 통과한 경우에만 저장한다.
- 익명 사용자 ID를 OAuth 계정에 연결하며 이메일 문자열로 계정을 병합하지 않는다.
- 책장 정렬은 전체 배열이 아니라 한 권과 목표 위치만 전송한다.
- 다른 탭에서 책장이 바뀐 경우 fingerprint가 다르면 저장을 거부한다.
- 서버 렌더링은 읽기 전용 Supabase 클라이언트를 사용하고 세션 갱신은 middleware가
  담당한다.
- 모바일 값은 `redesign.css`의 `@media (max-width: 760px)`에 두고, 2단 레이아웃의
  행 순서는 `@media (max-width: 1100px)`에서 명시한다.

## Kakao 로그인 확인 상태

버튼과 서버 흐름은 구현되어 있고, 운영 `/api/auth/start`가 Kakao 인증 화면으로 303
리다이렉트하는 시작 단계까지는 확인했다. 다만 2026-09-21 확인 시 운영
`auth.identities`에는 아직 Kakao identity가 없어, 코드 교환과 익명 계정 연결까지 끝난
실제 왕복은 한 번 더 확인해야 한다.

현재 Supabase 공식 가이드는 Kakao 동의항목에 `profile_image`와
`profile_nickname`을 설정하도록 안내한다. 이메일을 사용하지 않는 앱은
`account_email`을 생략하고 Supabase Kakao 공급자의 **Allow users without an email**을
켤 수 있다. `account_email`이 필요하면 Kakao Biz App 전환이 필요하다.

따라서 지금 정상으로 보이는 설정은 변경하지 않는다. 실제 로그인 직후 아래 세 가지가
모두 확인되면 완료로 닫는다.

1. `/api/auth/callback`이 오류 없이 원래 화면으로 복귀한다.
2. `auth.identities.provider = 'kakao'`가 생성된다.
3. 익명 상태에서 만든 대화와 보관 선택이 로그인 뒤 그대로 유지된다.

공식 설정 기준: [Supabase — Sign in with Kakao](https://supabase.com/docs/guides/auth/social-login/auth-kakao)

1. Kakao·Google OAuth와 익명 identity linking을 실기기에서 끝까지 왕복 검증한다.

3. 이어갈 대화의 선택 삭제·재접속 정렬을 운영 계정으로 한 번 확인한다.
4. 종료 설문 UI의 제출 범위를 결정한다.
5. 실제 운영 대화로 예시 전사를 교체할지 결정한다.

위 항목은 현재 운영 중인 첫 질문 → 대화 → 질문 이동 → 보관 → 다시 보기 흐름을 막지
않는다.
