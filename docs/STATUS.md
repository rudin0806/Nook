## 정책·구조 결정 (변하지 않는 것)

- **보유 기간**: 미결정 대화 24시간 / 휴지통 7일 / 탈퇴 즉시 / 재가입 차단 해시 30일.
  모두 migration의 `interval` 값과 일치하며 처리방침 §3과 대조 확인했다.
- **`이어갈 대화`와 `남겨둔 질문`은 다른 데이터다.** 앞은 아직 마치지 않은 세션
  (`list_recoverable_sessions`, TEMPORARY·24시간), 뒤는 사용자가 명시적으로 남긴 곁가지
  질문(`branch_questions`, KEPT·만료 없음)이다. PRD §17이 둘을 나눠 두었고 화면도 나눈다.
  생각 더미의 `이어갈 대화` 탭은 홈 패널과 **같은 `/api/recovery`를 읽는다** — 한 목록을
  두 자리에서 보는 것이지 복제가 아니다.
- **카드 넘김은 홈의 `이어갈 대화`에만 있다.** 생각 더미의 네 탭은 전부 목록이다.
- **이어갈 대화는 노드 개수를 조건으로 두지 않는다.** 첫 입력이 저장된 순간부터 카드가
  생긴다. 첫 질문 확정 전에 나간 경우가 이 목록의 존재 이유이므로 제외하면 되돌릴 것이
  없어진다. 노드가 없는 카드는 확정된 질문이 아님을 카드에서 밝힌다.
- **세션 갱신은 `src/middleware.ts`가 단독으로 한다.** Server Component는
  `src/lib/supabase/reader.ts`(`setAll`이 no-op)로 읽는다. 렌더 중 쿠키 쓰기는 Next.js가
  금지하고, Supabase는 리프레시 토큰을 회전시키므로 렌더에서 갱신하면 회원이 조용히
  로그아웃된다.
- **턴의 단계 시간은 `ai_stage_timings`에 남는다.** `LOAD / SAFETY / GENERATE / COMMIT`
  네 줄이고, `GENERATE`에서 `judge_logs.latency_ms`를 빼면 생성 단계가 떨어진다. 모델
  호출을 추가하지 않고 이미 일어나는 호출의 시간만 잰다. 발화·사용자·세션은 담지 않고
  `anon`·`authenticated`에 권한이 없다. 같은 값이 표준 출력에도 `nook_stage`로 나간다.
- **Judge reasoning effort는 `medium`이다** (2026-09-18 결정, 모델은 `gpt-5.6-sol` 그대로).
  운영 실측에서 한 턴이 평균 15.3초(n=7, 최소 9.7 / 최대 19.2)였고 그중 Judge 하나가
  평균 6.4초(입력 평균 5,998토큰 → 출력 257토큰)였다. **strict 31/31은 high에서 나온
  결과이므로 현재 설정을 보증하지 않는다.** 재평가는 유료 호출이며 아직 실행하지 않았다.
- **모델 슬롯 6개가 독립**이다(`NOOK_{SAFETY,START,NODE_ZERO,JUDGE,REFRAME,REFLECT}_*`).
  `judge_logs`에만 모델명이 기록되며 거기 `gpt-5.6-sol`이 찍혀 있다. 나머지 5개의 실제
  값은 Vercel 환경변수에만 있다.
- **브랜드**: 마크는 `Nook`, SUIT 800, 잉크 단색, 온점·꾸밈 없음.
  `components/nook/wordmark.tsx` 한 곳에서만 만든다.
- **UI 공통**: 제목은 `components/nook/page-heading.tsx`(kicker/title/subtitle, 34·27px,
  부제에 온점 없음). 아이콘 타일은 `nook-icon.tsx`의 `tile`. 포인트 컬러는 주 동작과
  활성 상태에만 쓰고, 예시 화면(`data-sample`)에는 한 점도 쓰지 않는다.
- **입력 필드의 포커스는 `textarea`가 그린다.** globals.css가 SEED 래퍼의 box·border를
  `!important`로 지우기 때문이다. SEED는 자기 포커스 링을 래퍼의 `::after`에 그리는데
  `border: 0`이 거기까진 닿지 않아 링이 두 겹으로 보였고, 그 `::after`는 이제 껐다.
- **시각은 `lib/format/datetime.ts`의 `formatSeoulDeadline`으로 찍는다.** `ko-KR`
  기본 출력은 초까지 나온다.

## DB·동시성

- 운영 적용 migration: 16건 + 동의/탈퇴/재가입/노드 제한/책 크기 관련 migration.
- `saved_thought_sessions.shelf_revision`: RLS 적용 단일 SELECT snapshot의 전체 책장
  ID/자리 fingerprint. 단조 증가 revision이 아니므로, 다른 탭 변경 뒤 순서가 원래와
  완전히 같아졌다면 충돌로 보지 않는다.
- `move_saved_session_checked`: 사용자별 잠금 → fingerprint 비교 → 일치할 때만 이동.
- 삭제 cascade는 운영에서 합성 사용자로 검증했고 트랜잭션을 전부 rollback했다.
- 동의 테이블에서 `authenticated`가 SELECT 외 권한을 갖지 않음을 테스트가 단정한다.

## 남은 관문

1. **지연 재측정.** effort를 `medium`으로 내리고 리전을 서울로 옮긴 뒤 운영에서 대화가
   한 번도 돌지 않았다. `ai_stage_timings`가 0행이다. 대화 한 번이면 Judge 변화,
   턴 전체 시간, 단계 분해가 한꺼번에 나온다.
2. **이야기 상세(`/drawer/:id`) UI 미점검.** 로그인이 필요해 로컬에서 못 봤다.
   대화 화면(`/talk/[nodeId]`)은 `/api/conversation` 응답을 목으로 넣어 실측했다.
3. **예시 대화 전사.** `src/lib/example/story.ts`의 `nodes`·`clarifications`를 실제 대화로
   교체하고 `transcriptPending`을 내린 뒤 홈에 칩을 연결한다. 운영에서 대화를 남기면
   Supabase에서 읽어올 수 있다.
4. **Kakao 로그인.** 타입에는 있고 UI에 없다. Supabase Auth 설정이 선행된다.
5. **종료 설문.** 가설 검증용이며 모델 학습과는 무관하다.
6. **프롬프트 문체.** 근거 문장이 `~했습니다` 체로 나와 RULES §10과 어긋난다. 프롬프트
   수정이라 유료 재평가가 필요하다.
7. 실기기 터치·실제 Google OAuth 왕복·만료 데이터 Cron 처리 관찰.
