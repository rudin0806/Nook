## 기능 구현 전 해결해야 하는 불일치·공백

| Safety의 결정론적 표현       | PRD §5.1의 “0~2는 결정론적”과 §8의 Moderation + 별도 Safety Classifier가 상충                  | Safety의 라우팅은 코드, 위험 분류는 모델로 구분. 결정론적이라고 부를 부분은 사용자 제어·구조 검사. 별도 Safety Gate 유지 |
| Clarification 표시 한도      | PRD §11은 한 Node 구간 2~~3개, §18 및 인수인계 §24·26은 한 구간 2~~3개                         | Node 단위인지 Segment 단위인지 확정 필요. 화면 구현 전 결정                                                              |

## 확인한 기술 근거

- Next.js 설치: https://nextjs.org/docs/app/getting-started/installation
- Next.js ESLint: https://nextjs.org/docs/app/api-reference/config/eslint
- SEED 공식 수동 설치: https://seed-design.io/react/getting-started/installation/manual
- SEED의 실제 설치 패키지 타입으로 TextField.Root / TextField.Textarea 검증
- Supabase SSR의 실제 설치 패키지 타입으로 getAll / setAll 쿠키 인터페이스 검증
- OpenAI SDK의 실제 설치 패키지 타입으로 서버 클라이언트 생성 인터페이스 검증

시장 가격, 대회 일정, Safety 연락처 및 서비스 비용의 최신성은 이번 초기화 검증 대상이 아니다.
관련 화면·배포 운영·외부 발표에 반영하기 전에 각각 공식 출처로 다시 확인한다.
