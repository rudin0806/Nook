# 첫 입력·질문 승인 화면 연결

기준 커밋: `adab239`, PR #2. 디자인 재작업은 보류하고 기존 입력 화면에 실제 API 호출과 상태 표시를 연결했다.

## 구현

- 첫 입력 → `/api/start`, 명시적 초점 선택 → `/api/start/focus`, 질문 확인/수정 후 승인 → `/api/start/approve`.
- UI 컴포넌트, 요청 상태 hook, 응답 검증 클라이언트를 분리했다. Supabase/OpenAI를 컴포넌트에서 호출하지 않는다.
- 홈은 서버의 `NOOK_START_API_ENABLED`에 따라 시작 가능 여부를 전달한다. 비활성 상태에서는 입력을 전송하지 않는다.
- 질문 제안과 승인 완료를 구분한다. 승인 완료는 정상 HTTP 상태와 UUID 응답을 검증한 뒤에만 표시한다. 승인 뒤 후속 대화 기능은 아직 준비 중임을 명시한다.
- NEEDS_INFO 안내, 초점 선택, 수정 가능한 첫 질문, STOP/HANDOFF 안내, 로그인 필요, 처리 중, 횟수 제한, 만료, 네트워크 오류를 각각 표시한다. 연락처는 서버 응답의 검증된 숫자 문자열만 사용한다.
- 같은 요청 처리 중 추가 클릭을 막는다. 응답 유실이나 RUNNING/429에서는 요청 ID와 본문을 메모리에 유지하고 사용자가 선택할 때 동일 요청만 재전송한다. 자동 재시도/새 요청 생성은 하지 않는다.
- 최초 입력의 성공 재전송이 Session ID만 반환하면 질문이 승인됐다고 표시하지 않는다. 제안을 복구할 수 없다는 안내와 명시적 재시작을 제공한다.
- 원문·질문·서명은 컴포넌트 메모리에만 둔다. URL/localStorage/sessionStorage/로그에 저장하지 않는다. 로그인 이동 또는 새로고침 시 입력/재시도 상태가 유지되지 않는 한계가 있다.
- 단계가 바뀌면 제목으로 키보드 포커스를 이동하고, 처리 상태는 aria-live로 알린다. 긴 후보는 줄바꿈하며 기존 팔레트를 유지한다.

## 검증

- 신규 클라이언트 테스트 7개, 전체 테스트 110개 통과.
- typecheck / lint / production build 통과. 변경 파일 formatting 및 diff 공백 검사 통과.
- 기존 API/DB 검증 결과는 [API 구현 기록](2026-09-14-start-api.md)을 따른다. 이번 작업은 DB를 변경하지 않았다.
- 실제 브라우저 검증은 미완료: agent-browser의 Chrome 설치가 인증서 오류로 실패했고, 신뢰 CA를 사용하는 Playwright 대체 다운로드도 시간 초과로 실패했다. 실제 클릭/레이아웃/모바일 동작을 확인했다고 보고하지 않는다.
- 실제 인증 → 모델 호출 → 저장 → 화면까지 전체 왕복은 미검증. 응답 계약 테스트는 실제 모델 평가를 대체하지 않는다.
