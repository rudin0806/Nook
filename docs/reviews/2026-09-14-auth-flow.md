# Google/Kakao 인증 연결 — 2026-09-14

## 구현 범위

- `/login`: Google·Kakao 시작 폼, 오류 안내, 이야기/생각더미 복귀, 이 기기 로그아웃.
- `POST /api/auth/start`: 서버 `getUser()`로 신원을 확인한다. 세션 없음은 `signInWithOAuth`, 익명 사용자는 `linkIdentity`, 영구 사용자는 기존 세션 유지. 연결 실패를 일반 로그인으로 우회하지 않는다.
- `GET /api/auth/callback`: SDK의 PKCE code exchange 뒤 다시 `getUser()`로 검증한다. 익명 연결은 원래 UID와 같고 `is_anonymous=false`여야 성공한다. 계정 간 기록 합치기·이메일 기반 재귀속·삭제를 하지 않는다.
- `POST /api/auth/signout`: 이 기기의 세션만 해제한다. 익명 사용자의 유일한 대화 접근권이 없어지지 않도록 익명 로그아웃은 거절한다.
- 생각더미 401 안내가 실제 계정 연결 화면으로 연결된다. 조사 `생각더미을`을 `생각더미를`로 수정했다.

## 요청 경계

서버 전용 `NOOK_SITE_URL`에 명시된 origin만 사용한다. 요청 헤더의 host/forwarded-host 및 사용자 `next` URL은 redirect 대상에 사용하지 않는다. POST는 Origin 일치가 필수이며 GET으로 로그인 시작·로그아웃할 수 없다. 공급자는 Google/Kakao로 제한한다.

로그인 흐름 쿠키는 HttpOnly/SameSite=Lax, HTTPS에서 Secure, 10분 만료다. 쿠키는 연결할 UID의 일치 확인용이며 인증·DB 권한 근거가 아니다. 인증의 근거는 Supabase PKCE 세션과 `getUser()`, 데이터 접근은 기존 RLS다. 콜백 응답은 no-store/no-referrer이며 공급자 오류 원문·코드·토큰을 화면이나 로그에 출력하지 않는다.

## 배포 설정

1. 배포 환경에 기존 `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`와 `NOOK_SITE_URL`을 설정한다. 마지막 값은 해당 배포의 고정 origin(예: `https://nook-nine-eta.vercel.app`)이며 경로·쿼리를 붙이지 않는다. 프리뷰는 프리뷰 origin을 따로 지정한다.
2. Supabase Auth에 Google/Kakao 공급자를 설정하고 identity linking을 위한 **Manual Linking**을 활성화한다. 공급자 콘솔의 callback은 Supabase가 안내하는 Auth callback URL이다.
3. Supabase Redirect URLs에는 앱의 `<NOOK_SITE_URL>/api/auth/callback`을 허용한다. 공급자 콘솔 callback과 앱 callback은 서로 다르다.
4. 배포 후 일반 로그인, 익명 UID 보존, 기존 다른 계정과 연결 충돌, 취소/만료/재시도, 로그아웃, 타 사용자 데이터 차단을 실제 브라우저와 DB에서 검증한다.

공식 근거: [익명 사용자와 identity linking](https://supabase.com/docs/guides/auth/auth-anonymous), [linkIdentity](https://supabase.com/docs/reference/javascript/auth-linkidentity), [서버 인증 클라이언트](https://supabase.com/docs/guides/auth/server-side/creating-a-client).

## 검증 결과와 한계

- `npm run test:auth`: 정책·흐름 단위 테스트 6/6. 연결 실패 시 일반 로그인 미호출, Auth 장애 시 신규 로그인 미호출, origin/공급자/만료/UID 검증 포함.
- `npm run validate`: 타입·린트·프로덕션 빌드 통과.
- 프로덕션 서버 로컬 HTTP smoke 7/7: 로그인 페이지, 시작·로그아웃 GET 거절, 외부 Origin 거절, 허용 외 공급자 거절, 설정 없는 시작 오류 redirect, 흐름 없는 callback 거절.
- 실제 Google/Kakao 왕복 및 연결 충돌은 미검증. Supabase 공급자 설정·운영 DB·Vercel 환경변수를 이번 작업에서 변경하지 않았다. 유료 AI 호출 0회.
- 익명 사용자 생성과 첫 대화 연결, 보관 결정을 들고 OAuth 뒤 원래 종료 화면으로 복귀하는 동작은 남았다. 현재 성공 후 목적지는 `/drawer`다. 기존 계정 충돌 시 자동 병합/익명 세션 복구는 구현하지 않았다.
- 여러 탭에서 동시에 시작하면 마지막 PKCE/흐름 쿠키만 유효하다. 앞선 탭은 실패 안내 뒤 재시도한다.
