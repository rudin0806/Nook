# 종료·복귀·보관·재시작 구현 — 2026-09-15

사용자 승인에 따라 PRD의 기능 항목과 RULES §12의 상태별 보관 계약을 갱신했다. 별도 중간 저장은 없으며 생각 더미에는 명시적으로 남긴 기록만 들어간다. 저장을 해결 판정으로 취급하지 않는다.

## 검증

- 타입 검사·린트·프로덕션 빌드 통과. 기존 Turbopack 캐시 손상과 캐시 디렉터리 정리 오류를 피하기 위해 로컬 생성 캐시를 분리하고 깨끗한 빌드로 확인했다.
- 로컬 프로덕션 HTTP 검사: 홈/재시작/복귀/휴지통 경로 200, 잘못된 UUID 400, 보관 요청의 다른 Origin 403. Supabase 미설정 환경의 새 조회 API는 503 + no-store로 데이터를 노출하지 않았다. 이는 실제 인증 성공/실제 DB 연결 검증이 아니다. 로컬 Next 서버는 환경의 네트워크 인터페이스 열거 제한 때문에 127.0.0.1 명시 바인딩으로 실행했다.

- 오프라인 테스트 137개: 기존 132개와 복구 서명/기한, Safety 초안 제외, 재시작 입력 계약, 승인 전 보관 표시 검사 5개.
- 독립 PGlite에서 전체 migration 10개와 SQL 테스트 7개: 만료 경계, 기존 RLS/삭제 연쇄/시작 승인/대화 회귀와 신규 session_recovery 시나리오.
- 새 DB 시나리오: 다중 복귀와 기한 유지, PENDING Branch 재시작, SAVED Node 재시작, 승인 전 보관 입력 재시작, 출처 삭제 후 자식 보존, ACTIVE 직접 저장, 동일 선택 재전송, 늦은 AI 응답 거절, 다른 소유자 차단, 지연된 만료 기한 및 익명/Safety 예외.
- `npm run eval:validate`: issues 0. 실제 모델 평가는 이번 보관 변경에서 재실행하지 않았다. 기존 C/D 6/6 완주와 Judge strict 30/31 결과는 역사적 결과로 유지한다.
- 실제 Auth/HTTP/DB/모델을 잇는 통합 검증과 복수 브라우저 동시성 검증을 이 독립 테스트로 대체하지 않는다.
