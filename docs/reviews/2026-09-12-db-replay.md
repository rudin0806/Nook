## 발견한 실패와 보완

보조 함수 `public.rls_auto_enable()`는 Nook migration이 생성하지 않는다. 함수가 없는 빈 DB에서는 마지막 migration의 REVOKE가 실패했고, 트랜잭션 전체가 취소됐다.

마지막 migration의 해당 구문만 함수 존재 여부 검사로 감쌌다. 이미 적용된 서버 동작을 바꾸는 새 migration이 아니라 신규 환경 재생을 위한 호환성 수정이다. 기존 원격 SQL과 이 차이는 의도적으로 기록한다. 함수가 존재하면 이전과 동일하게 PUBLIC/anon/authenticated 권한을 회수한다. 원격에는 다시 적용하지 않았다.

## 실행 검증

- 독립 PGlite PostgreSQL 엔진에서 migration 4개를 처음부터 순서대로 실행.
- 보조 함수 없음/있음 두 환경에서 적용 및 RLS SQL 통과. 함수가 있을 때 anon/authenticated 실행 권한 회수 확인.
- 동일한 `supabase/tests/retention_rls.sql`을 원격 NOOK에서 실행하고 ROLLBACK.
- 본인 세션·뷰 조회, 타 사용자 조회 차단, 사용자 변경 RPC 8개 타인 대상 거절.
- 클라이언트 직접 UPDATE 차단, Judge/Safety 로그 조회 차단.
- 저장, 7일 휴지통, 복원, 익명 보관 거절, 익명 미보관 즉시 삭제.
- public 앱 테이블 13개 RLS, 조회 뷰 security_invoker 확인.
- 합성 사용자와 세션은 트랜잭션 전체 롤백. 운영 스키마·데이터 변경 없음.

## 범위와 남은 작업

Docker/CLI가 없고 로컬 PostgreSQL 설치도 실행 환경 권한으로 실패했다. PGlite 검증은 Supabase 전체 reset을 대체하지 않는다. auth.users 및 auth.uid()/auth.jwt()는 테스트 최소 구현이며, pgcrypto 설치 한 줄은 생략한다(PostgreSQL 내장 gen_random_uuid 사용). 실제 Auth 발급·HTTP API·동시 요청·스토리지·Supabase 플랫폼 확장은 검증하지 않았다.

원격 security advisor는 의도된 authenticated SECURITY DEFINER RPC 경고 9건을 반환했다. 이번 소유권 테스트를 통과했지만 경고가 사라졌다고 주장하지 않는다.

**pg_cron 미설치**: `purge_expired_sessions()`와 예약 SQL 파일은 있지만 자동 정리는 동작 중이 아니다. 예약 활성화는 삭제를 시작하는 운영 변경이므로 이번 재현 검증에는 포함하지 않았다. 기존 만료 데이터 범위 점검 후 활성화·실행 이력 검증이 필요하다.

별도 Supabase 테스트 환경의 전체 reset, Branch/Anchor 삭제 연쇄, 만료 정리 실행, 실제 인증/API 통합 검증은 후속 단계다. 이번 검증으로 DB 전체 개발 완료를 주장하지 않는다.
