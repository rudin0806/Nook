# C-02 수령·정합 검토

수령: C-02-prompt-d.md, prompt-reflect.ts. Judge 기준 4bc6b30 (PR #2). Claude 문서 원문은 docs/proposals/C-02-prompt-d.md에 보존한다. 원문의 제안·실행 상태와 이 통합 기록을 구분한다.

## 반영

- REFLECT 전용 요청 준비 함수. 검증된 Judge 출력이 SHIFT/CLOSE면 거절하며 재판정하지 않는다.
- medium_reason은 MEDIUM에서 필수, LOW에서는 null. 기존 Judge Zod 검증을 재사용하고 그대로 D에 전달한다.
- past_allowed는 past_probe_count=0이며 직전 질문이 PAST가 아닐 때만 true. 출력 검증에도 동일 조건을 적용한다.
- 출력은 question/type만 허용. 빈 질문·알 수 없는 타입·lead_in 등 추가 필드 거절.
- Judge 근거가 현재 사용자 발화 또는 명시적 carryover에 실제 존재하는지 검사한다. 명시적 carryover 본문만 전달하며 전체 history를 보내지 않는다.
- 누락된 중심 질문으로 일반 D를 호출하지 못하게 한다.

## 첨부본 보완

1. 질문 한 문장만 출력 vs JSON만 출력의 모호함 → JSON question 값이 한 문장이라고 명시.
2. D-03과 시스템 예시에 입력에 없는 '회의'가 추가됨 → 시스템 예시의 해당 장소 추정 제거. 원문 D-03은 검토가 필요한 제안 사례로 유지.
3. PAST 경험 확인 vs 반복 성향 탐색 금지의 범위를 문장으로 구분.
4. 모든 감정이 재료가 아니라는 단정 → 장면/관찰 사실 사용, 감정 이름만으로 이동을 확정하지 않는다는 규칙으로 정리.
5. LOW도 명시적으로 전달. MEDIUM 사유와 과거 질문 권한을 프롬프트 지시만으로 보장하지 않고 코드 경계에서 검증.

## 자동 검사 범위

물음표 복수, ~것 같아요 종결, ~군요 종결을 진단 정보로 제공한다. 이 진단은 모델 출력의 의미 평가나 실행 허가를 대체하지 않는다. '자주' 일괄 금지는 D-08의 정상 빈도 질문을 오탐하므로 적용하지 않는다. 두 질문이 물음표 하나로 합쳐지거나 문맥상 방향을 유도하는 경우는 의미 검토가 필요하다.

D-01/03/05/06 및 시스템 예시가 Judge fixture와 겹친다. 같은 문장 일치는 일관성 확인이지 독립 성능 증거가 아니다. 첨부 8개는 사람이 작성한 예시이고 모델 평가 결과가 아니다. 토큰 수 1,935도 전달받은 측정치이며 수정 후 재측정하지 않았다.

## 실행·보류

```sh
node --experimental-strip-types --test tests/reflect.test.mts
npm run validate
```

8개 단위 테스트로 분기, MEDIUM 사유, 과거 질문 상한, 스키마, 근거 전달, 빈도 질문 오탐 방지를 확인했다. 실제 모델 호출·DB 저장·API 배선은 아직 없다. 상위 호출부는 Safety → 사용자 종료 의사 → 구조적 상한을 먼저 통과해야 한다. 출력 PAST를 사용자에게 제공할 때 과거 질문 카운터를 원자적으로 소비하는 DB 연결도 후속 작업이다.

focus_required의 확인 질문 담당은 RULES 1.3에 없다. A 출력 확장 또는 시작 UI 고정 질문 모두 가능하다. D 호출 조건을 확장하지 않았다. 선택지 표기, 1회 확인 이후 재입력 처리, start fixture 확장은 결정 후 함께 구현한다.
