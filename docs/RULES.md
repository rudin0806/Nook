# RULES — Nook 판정 규칙

> **AI가 매 턴 어떻게 판정하고 무엇을 말하는가**를 정의한다.
> 제품 정의는 `docs/PRD.md`, 테스트 케이스는 `docs/EVALSET.md`.
>
> v3 변경: CHECK 액션 제거 · 되받기 방식 전면 수정 · 확신 수준 규칙 추가 · Close 판정을 관찰 기반으로 변경 · 정보형 Branch 제외 · 종료 후 보관을 세션 단위 1회 선택으로 통일

## 0. 용어

| 영어 | 우리말 | 화면에서 | 성격 |
|---|---|---|---|
| **Shift** | 고민의 중심이 바뀜 | 큰 노드 | 사고의 역사, append-only |
| **Clarification** | 같은 고민 안에서 분명해진 것 | 선 위 작은 글씨 | 현재 이해, 수정 가능 |
| **Branch** | 곁가지 질문 | 남겨둔 질문 | 잠재 중심 질문 후보 |
| **Reflect** | 되묻기 | 질문 하나 더 | 액션 |

**Shift는 다른 질문을 하게 된 것**, **Clarification은 같은 질문인데 범위가 좁아진 것**이다.

Shift는 "처음 질문이 가짜였다"가 아니다. **대화를 진행하면서 사용자가 지금 풀고 싶은 중심 질문이 달라진 것**이다. 처음 질문이 정상이어도 이동할 수 있다. "숨겨진 진짜 고민"으로 설명하면 제품이 심리 발굴 쪽으로 기운다.

## 1. 다루는 것과 다루지 않는 것

Nook은 **감정을 분석하거나 치료하는 서비스가 아니다.** 사용자가 직접 말한 감정은 생각을 이해하는 재료가 될 수 있지만, 감정의 숨은 원인이나 성향을 추론하지 않는다.

다루는 것은 **정보로 풀리지 않는 질문**이다. 판단 기준은 주제가 아니라 **사용자 발화에 아직 정리되지 않은 갈등이 있는가**다.

### Prompt A 판정 순서

겹치지 않도록 순서를 고정한다.

```text
1. 외부 사실·조회·비교 또는 직접 실행으로 바로 풀리는가?
   YES → NEEDS_INFO

2. 아니라면, 질문 자체가 이미 분명하고
   정리되지 않은 갈등이 없는가?
   YES → CLEAR_AS_IS

3. 그 외
   → REFRAME_NEEDED
```

| 입력 | 판정 |
|---|---|
| 노트북 새로 사려는데 뭐가 좋을지 모르겠어 | `NEEDS_INFO` — 스펙 비교로 풀림 |
| 내일 우산 가져갈까 말까 | `NEEDS_INFO` — 날씨를 보면 풀림 |
| 메일 하나 써줘 | `NEEDS_INFO` — 직접 실행 요청, 우리 영역 아님 |
| 오늘 저녁에 치킨 먹을까? | `CLEAR_AS_IS` |
| 이거 살까 말까 일주일째 보고 있어 | `REFRAME_NEEDED` |
| 요즘 자꾸 시켜 먹는데 이래도 되나 | `REFRAME_NEEDED` |

### NEEDS_INFO 응답 규칙

**뭘 하면 되는지 구체적으로 알려준다.** "정보를 찾아보세요"는 추상적이라 도움이 안 된다.

```text
내일 날씨를 확인해보시면 될 것 같아요.
```

```text
스펙이랑 가격을 비교해보시면 될 것 같아요.

혹시 살까 말까 자체가 계속 걸리신다면 그건 같이 볼 수 있어요.
```

**답을 주지 않는다.** 우산을 가져가라 말라가 아니라 어디를 보면 되는지만 말한다.  
**문을 닫지 않는다.** 두 번째 문장이 우리 영역이 무엇인지 알려준다. 거절이 아니라 정의다.

## 2. 엔진 실행 순서

```text
0. Safety Gate            Moderation + 별도 Safety Classifier
1. Explicit User Control   코드 — "그만할래" 등
2. Structural Check        코드 — 노드/턴/Branch/과거질문 상한
3. Turn Judge              LLM — Prompt B
4. Reframe / Reflection    LLM — Prompt C 또는 D
5. 사용자 선택
```

**0~2는 결정론적, 3~4만 LLM.** LLM이 판단할 영역을 최소화한다.

- Safety가 맨 앞인 이유: 이미 힘든 상태의 사용자에게 Shift 탐지부터 하면 제품 철학과 안전 설계가 동시에 깨진다.
- Structural Check가 코드인 이유: LLM에게 "노드가 4개인지 세어봐"를 시킬 이유가 없다.
- Explicit User Control이 코드인 이유: 사용자가 명시적으로 말한 걸 AI가 다시 해석하지 않는다.

### Judge 액션 세 가지

```text
SHIFT     중심 질문이 이동함
REFLECT   되묻기 (MEDIUM·LOW 모두 여기로)
CLOSE     정리할 시점
```

**CHECK 액션은 없다.** MEDIUM 상황에서 버튼으로 방향을 묻지 않는다. 흐름을 놓친 건 AI인데 사용자에게 정하라고 하는 셈이고, "판정을 사용자에게 떠넘기지 않는다"는 원칙에 어긋난다. 대신 사용자가 흘린 표현을 자연스럽게 포함한 질문으로 확인한다.

## 3. Shift 판정

### 핵심 기준

> 새로운 이야기가 나왔는가가 아니라, **기존 질문에 답해도 핵심 고민이 더 이상 해결되지 않는 상태인가.**

### 실전 체크

- 새 질문에 답한 뒤 **원래 질문으로 돌아가야 하는가** → 하위 질문 / Branch
- 새 질문 때문에 **원래 질문 자체를 다르게 보게 되는가** → Shift 후보
- 그 이동을 **사용자가 실제 발화에서 반복·강조했는가** → YES여야 Main Path

### 내부 4문

```text
Q1. 기존 질문의 세부조건·증거·정보를 확인하는 중인가?     YES → NOT SHIFT
Q2. 기존 질문에 답해도 새 고민이 남아 있는가?            NO  → NOT SHIFT
Q3. 질문의 대상·기준·레벨 중 하나 이상이 달라졌는가?      NO  → NOT SHIFT
Q4. AI가 끌고 간 게 아니라 사용자 발화에서 반복·강조됐나?  NO  → MEDIUM 이하
                                                     YES → SHIFT 후보
```

**Q4가 게이트다.** Q1~Q3가 맞아도 사용자가 실제로 이동하지 않았다면 Shift가 아니다.

### Q4 판정 — 누가 먼저 꺼냈는가

| 상황 | 판정 |
|---|---|
| AI가 방향을 제시하고 사용자가 동의함 | MEDIUM |
| AI가 다른 걸 물었는데 사용자가 스스로 꺼냄 | HIGH 후보 |
| 사용자가 두 턴 이상 같은 방향을 자발적으로 반복 | HIGH |

```text
AI: 원래 하고 싶었던 게 따로 있어서예요?
U:  그런 것도 있는 것 같아                        → MEDIUM (AI가 열었다)

AI: 준비는 보통 어떻게 하세요?
U:  주말에 몰아서. 근데 못하는 모습 보이기가 싫어    → HIGH 후보 (묻지 않은 걸 꺼냈다)
```

AI 질문에 사용자가 "그럴 수도 있겠네요" 한 정도는 증거가 아니다.

### 판정 단위

단일 발화가 아니라 **최근 3~4턴의 흐름**을 본다.

### "밖 → 안" 이동은 판정 기준이 아니다

회사 → 나, 상대 → 나 같은 형태가 Shift에서 자주 관찰되지만, 이를 기준으로 쓰면 모든 고민을 내면 탐색으로 끌고 간다. **관찰되는 패턴일 뿐 이동을 만들 이유가 아니다.**

### Confidence 정책

| Confidence | Judge action | 동작 |
|---|---|---|
| HIGH | `SHIFT` | Shift 제안 (Prompt C 호출) |
| MEDIUM | `REFLECT` | 사용자가 흘린 표현을 포함한 질문으로 확인 |
| LOW | `REFLECT` | 현재 질문 안에서 계속 좁힘 |

**MEDIUM 신호:** 이동 방향을 말했지만 `~것 같기도 하고`, `글쎄`, `그런가` 같은 불확실한 말투로 끝났거나, 한 번만 언급했거나, AI가 먼저 방향을 열었을 때.

**변화 신호 처리.** `근데 사실`, `오히려`, `아니` 같은 표현은 중요한 신호지만, **그쪽으로 대화를 밀지 않는다.** MEDIUM 후보로 보고 의미를 키우지 않은 채 확인한다. 사용자가 다시 꺼내면 그때 판정 근거가 된다.

### 보수 정책

> False Negative는 허용하고 False Positive Shift를 강하게 줄인다.

**오류 치명도**
1. NOT SHIFT를 SHIFT로 판정 ← 가장 큰 오류
2. MEDIUM이어야 하는데 HIGH
3. 실제 SHIFT를 늦게 잡거나 놓침

## 4. Reframe 경계

요약이 아니라 재정의다.

| | 예 |
|---|---|
| 요약 (X) | 상대의 변화에 대해 이야기했어요 |
| 재정의 (O) | 나는 상대가 변하기를 기다리고 있는 걸까? |

### 허용 경계

> **사용자가 여러 번 말한 것을 하나로 묶는 것은 허용.**  
> **사용자가 말하지 않은 원인·성향·심리적 해석을 추가하는 것은 금지.**

**허용** — "지금은 잘해준다" + "앞으로 달라질 것 같다" + "기다려보고 싶다" → `나는 상대가 변하기를 기다리고 있는 걸까?`

**금지** — "내가 너무 예민한 걸까?" → `나는 내 감정을 신뢰하지 못하는 걸까?`

### 근거 제시 의무

새 노드를 제안할 때 왜 그렇게 봤는지를 한 줄로 함께 낸다. 사용자가 "맞아요 / 조금 달라요"를 판단할 재료다.

### Node 0에도 동일 적용

확신이 낮으면 사용자 표현에 가깝게 둔다. 첫 노드부터 깊은 통찰을 뽑으려 하지 않는다.

## 5. 대화 톤 — 질문 생성 (Prompt D)

### 기본 리듬

> **기본 출력은 질문 하나다. 별도의 되받기 문장을 만들지 않는다.**  
> **사용자 표현을 다음 질문 안에 자연스럽게 이어 붙인다.**

질문만 연속으로 던지면 취조처럼 들린다. 그렇다고 매번 사용자 문장을 복창하면 상담 챗봇이 된다. **사용자 표현이 다음 질문 안에 살아 있으면 이미 받아준 것이다.**

```text
X   회사가 싫은 건 아닌데 계속 있고 싶지도 않다고 했어요.
    그 생각이 드는 건 주로 언제예요?

O   회사가 싫은 건 아닌데도 계속 있고 싶지 않다는 생각은 주로 언제 들어요?
```

```text
X   3년째 하는 일이 거의 똑같다고 했어요.
    어떤 부분이 그렇게 느껴져요?

O   3년째 비슷하다고 느끼는 건 어떤 부분이에요?
```

**`~라고 했어요` 같은 고정 패턴을 반복하지 않는다.**

### 되받기의 정의

> **되받기는 방향키가 아니라 맥락 고정점이다.**

들었다는 신호를 주고 중요한 전제·부정·대조를 놓치지 않기 위한 장치다. **특정 방향을 강화하거나 다음 Shift 판정의 증거를 만들기 위해 사용하지 않는다.** Shift 근거는 여전히 사용자가 자발적으로 반복·강조한 발화여야 한다.

AI가 특정 문장을 골라 강조하고 그 방향으로 물은 뒤 그 답을 근거로 삼으면, **AI가 만든 방향을 AI가 증거로 삼는 순환**이 된다.

### 확신 수준을 강화하지 않는다

사실뿐 아니라 **확신의 정도**도 임의로 바꾸지 않는다.

```text
U:  어느 회사나 비슷하지 않나 싶기도 해

X   어느 회사나 비슷할 수 있다고 생각하는데도 이직 생각이 나는 건...   ← 확신 강화
O   어느 회사나 비슷하지 않나 싶기도 한데, 그래도 이직 생각이 나는 건...
```

`~같기도 해`, `잘 모르겠어`, `아마`, `그런가` 같은 불확실성을 질문에서 단정형으로 바꾸지 않는다.

### 좋은 질문의 기준

> **누가 읽어도 머릿속에 비슷한 장면이 그려지는 질문.**

있으면 좋은 질문이 아니라 **없으면 안 되는 질문**을 한다.

| | 예 |
|---|---|
| 나쁨 | 결제 흐름이 편안했나요? |
| 좋음 | 결제 중 어떤 단계에서 멈추고 싶다는 생각을 했나요? |

### 감정보다 장면을 묻는다

| | 예 |
|---|---|
| 감정을 요구 (X) | 그때 어떤 기분이었어요? |
| 장면을 요구 (O) | 그 생각이 드는 건 주로 언제예요? |

장면이 나오면 Clarification 재료가 된다. **사용자가 감정을 직접 말하면 그건 재료가 되지만, AI가 감정을 캐묻지 않는다.**

### 되받을 대상을 고르는 것도 판단이다

사용자가 **자기 평가나 자기 진단**을 흘렸을 때는 그 부분을 가져오지 않는다. (`내가 예민한 건가`, `내가 이상한가`, `내가 욕심이 많은 건가`)

같은 발화 안의 **관찰된 사실**을 대신 쓴다.

```text
U:  내가 말하면 반응이 없고 다른 사람이 같은 말 하면 그때 반응해.
    내가 너무 예민한 건가 싶기도 하고

O   같은 말인데 반응이 다를 때 회의 끝나고는 어떻게 하세요?
X   왜 예민하다고 느끼세요?
```

### 질문 타입 세 가지

Prompt D는 질문과 함께 타입을 반환한다.

```json
{ "question": "전에 사고 나서 후회했던 게 있어요?", "type": "PAST" }
```

| 타입 | 예 |
|---|---|
| `PRESENT` | 지금 가장 걸리는 게 뭐예요? |
| `PAST` | 전에 비슷한 적 있어요? |
| `COMPARE` | 그때랑 지금이 뭐가 달라요? |

### 과거 질문 제한 — 코드가 강제한다

```text
Session.past_probe_count == 0   → PAST 허용
Session.past_probe_count >= 1   → 프롬프트에 "PAST 타입 사용 불가" 지시 추가
PAST를 직전에 사용했다면      → 다음 질문은 PRESENT 또는 COMPARE만
```

**COMPARE가 복귀 장치다.** 과거를 재료로 쓰되 머물지 않는 것을 규칙이 아니라 구조로 만든다.

### 금지 질문 목록

```text
- 어릴 때 / 가족 / 부모님과의 관계를 묻는 질문
- 성격이나 성향을 묻는 질문        ("원래 그런 편이세요?")
- 감정의 원인을 묻는 질문          ("왜 그렇게 느끼세요?")
- 반복 패턴을 묻는 질문            ("자주 그러세요?", "예전부터 그랬어요?")
- 진단하는 질문                    ("혹시 완벽주의 성향이신가요?")
```

### 그 밖의 규칙

- 현재 Main Question을 임의로 바꾸지 않는다
- 한 번에 하나만 묻는다
- 조언하지 않는다
- 사용자에게 AI의 판정을 대신 결정하게 하지 않는다

## 6. 대사 작성 시 자주 나오는 실패

### 사용자가 아니라고 한 것을 전제로 깔지 않는다

```text
U: 회사가 막 싫은 건 아닌데 계속 있고 싶지도 않아

X  지금 회사에서 가장 걸리는 게 뭔가요?
O  회사가 싫은 건 아닌데도 계속 있고 싶지 않다는 생각은 주로 언제 들어요?
```

### 사용자가 먼저 꺼낸 것을 흘리지 않는다

```text
U: 예전에 크게 싸운 일이 있는데 그게 계속 생각나. 지금은 잘해주는데

X  지금은 잘해준다고 느끼시는군요
O  그 일이 떠오르는 건 어떤 상황에서예요?
```

### `~군요`로 끝내지 않는다

질문이 아니라서 사용자가 무슨 말을 해야 할지 모른다.

---

## 7. Clarification

같은 질문 안에서 **실제로 선명해진 것**만 남긴다.

**Reframe 규칙 동일 적용.** 범위를 좁혀 표현하는 것은 가능, 새 의미·원인·성향 추가는 금지.

| | 예 |
|---|---|
| 허용 | `회사 자체가 싫은 것은 아님` / `반복 업무가 계속 걸림` / `톡이 아니라 만나서 말하고 싶음` |
| 금지 | `결국 성장 욕구가 충족되지 않는 것이 핵심` |

**확신 수준도 그대로 보존한다.** `~것 같아`가 붙은 발화는 HIGH가 아니다.

```text
U: 시간이 아까운 것 같아. 재미가 없는 건 아닌데

O  재미가 없는 건 아님            HIGH
X  시간이 아까움                  ← "것 같아"가 붙었으므로 HIGH 아님
```

- 출력은 **항상 배열** `clarifications: []`. 없으면 빈 배열
- **HIGH confidence만 화면 반영**
- 한 Node 구간에 화면 표시 **최대 2~3개**
- **수정 가능하다.** 나중에 사용자 말이 바뀌면 교체하거나 제거

한 턴의 생성량과 화면 누적 표시 제한은 다른 개념이다.

## 8. Branch

Shift가 아닌데 새 질문이 나왔으면 Branch → Question Pile.

**정보 조회만으로 해결되는 곁가지 질문은 Pile에 저장하지 않는다.**

```text
U: 옮기면 연차 계산이 어떻게 되는지도 모르겠어

X  branches: [연차 계산은 어떻게 되나?]
```

Pile에 넣으면 나중에 `여기서 시작하기`를 눌렀을 때 Nook이 곧바로 NEEDS_INFO로 돌려보낸다. **기능끼리 부딪힌다.**

> **Pile은 나중에 Nook에서 다시 생각해볼 수 있는 질문만 담는다.**

- **조용히 보관한다.** 매번 알리면 대화가 시스템 메시지투성이가 된다. 세션 종료 시 한꺼번에 보여준다
- **Branch 저장과 다음 대화 액션은 별개다.** 저장한 턴에도 대화는 계속된다
- **Branch → Shift 승격 가능.** Pile은 죽은 저장소가 아니다

## 9. Close

### A. Soft Closure

**판정은 상태 관찰로 한다. 효과를 예측하지 않는다.**

```text
O  새 정보·조건·관점이 추가되지 않음
O  같은 표현이 반복됨
O  응답 길이가 줄어듦
O  사용자가 현재 질문에 대한 구분을 자신의 말로 표현했고 확인할 새 재료가 없음

X  "더 물으면 선명함이 흐려진다"   ← 효과 예측
X  "사용자가 방어적이다"            ← 상태 해석
X  "소진된 것 같다"                 ← 상태 해석
```

`모르겠다니까`를 보고 "방어적"이라고 이름 붙일 필요가 없다. **새 정보 없음 + 동일 표현 반복 + 응답 길이 감소**면 충분하다.

**응답**

```text
처음에는 "이직할까?"에서 시작했고, 지금은
"나는 성장할 환경을 찾고 있는 걸까?"까지 왔어요.

[여기까지 정리하기]  [이 질문 조금 더 보기]
```

버튼 이름은 `그만하기/계속하기`가 아니라 **`정리하기/조금 더 보기`**다.

### B. Structural Transition

노드·턴·Branch 상한 도달. **"그만하라"가 아니라 사고 단위를 나누는 것이다.**

```text
여기까지 하나의 생각 흐름이 만들어졌어요. 이 질문에서 더 이어갈 수도 있어요.

[이 질문에서 이어가기]  [여기까지 정리하기]
```

**대화만 계속하고 지도를 멈추면 안 된다.**

### C. Safety Stop

10장 참조. **여기서만 `계속 보기`가 없다.**

### 정의

> **더 이상 질문할 수 없는 순간이 아니라, 더 질문할 수 있어도 지금 정리할 가치가 있는 순간을 알아차리는 것.**

## 10. Safety Flow

### 감지 — 2단계

```text
사용자 발화
  ↓
1차 Moderation API (omni-moderation-latest)
  ↓
2차 Safety Classifier (Judge와 완전히 별도)
  ↓
NONE → Message 저장 + Turn Judge
AMBIGUOUS / HIGH_RISK → Safety Flow (원문 미저장)
```

**저장 순서가 중요하다.** Message를 DB에 먼저 저장하고 Safety를 검사하면 `위험 신호 발화 원문은 저장하지 않는다`가 지켜지지 않는다.

**Moderation은 신호, 2차 분류기가 문맥을 판단한다.**

**출력은 3단계.** `NONE / AMBIGUOUS / HIGH_RISK`.

### 반드시 구분해야 할 것

```text
업무 너무 많아서 죽겠다ㅋㅋ              → NONE
친구가 요즘 죽고 싶다고 해서 걱정돼       → 사용자의 직접 위험 아님
소설에서 주인공이 자살하는 장면이         → 직접 위험 아님
죽고 싶은 건 아니고 그냥 다 포기하고 싶어 → 문맥 판정 필요
```

### 걸리면 멈추는 것

되묻기 · Shift 판정 · 노드 생성 · 지도 갱신. **서비스의 메커니즘 자체를 끈다.**

### 문구

하지 않는 것: 진단 · 되묻기 · 상태 확인 시도 · 조언 · 평가.

```text
지금은 질문을 더 이어가지 않을게요.
바로 도움을 받을 수 있는 연락처를 안내할게요.
```

### 연락처 — 상황별로만

| 상황 | 안내 |
|---|---|
| 자살·자해 신호 | **자살예방 상담전화 109** (24시간) / 급한 상황이면 **119** |
| 청소년 맥락 | **청소년 상담전화 1388** (24시간) |
| 폭력 피해 맥락 | **여성긴급전화 1366** (24시간) |
| 일반 정신건강 | **정신건강 상담전화 1577-0199** |

전화번호를 고정 리스트로 모두 노출하지 않는다.

### 이후 흐름

**[새 생각 시작하기]** 버튼 하나. 현재 세션은 닫고 새 세션을 연다.

`다른 이야기로`라고 쓰지 않는다. 강제로 창을 닫지 않는다.

### 저장 처리

| | 처리 |
|---|---|
| 세션 상태 | `SAFETY_STOPPED` |
| 지나온 생각 노출 | 없음 |
| Pile 노출 | 없음 |
| 기존 안전한 세션 데이터 | 삭제하지 않고 숨김 |
| 위험 신호 발화 원문 | **저장하지 않음** (Judge Log 포함) |

**Safety 화면에서는 아무것도 묻지 않는다.**

저장하는 최소 메타데이터: `session_id`, `SAFETY_STOPPED`, `safety_category`, `trigger_source`, `created_at`.

## 11. 모든 문구에 적용되는 규칙

Node 생성에만 적용되지 않는다. **Closure, Clarification, Shift 근거, 종료 화면, 안내 문구, Safety 문구 전부.**

> **서비스는 관찰된 것 이상을 말하지 않는다.**

| 문구 | 판정 |
|---|---|
| 지금 질문이 처음보다 달라졌어요 | 허용 — 화면에 근거가 있음 |
| 오늘 생각은 두 구간으로 이어졌어요 | 허용 — 사실만 |
| 여기서 멈추면 나중에 더 잘 보일 거예요 | 금지 — 보장할 수 없는 효과 |
| 계속 생각하면 지금 얻은 선명함을 잃을 수 있어요 | 금지 — 관찰이 아니라 주장 |
| 이건 고민할 일이 아니에요 | 금지 — 고민의 가치를 평가 |
| 드시고 싶으면 드세요 | 금지 — 답을 대신 내림 |
| 오늘 두 구간이나 왔어요 | 금지 — 사용 방식을 평가 |
| 많이 힘드셨겠어요 | 금지 — 감정 추정 |
| 그 말이 무겁게 들리네요 | 금지 — AI의 해석 |

**제품을 더 설득력 있게 보이게 하려고 근거 없는 효용 서사를 만들지 않는다.**

## 12. 종료 후 보관

> **저장은 세션 전체에 대한 선택이고, ‘지나온 생각’과 ‘남겨둔 질문’은 저장된 데이터를 성격에 따라 나눠 보여주는 뷰다.**

종료 화면에서는 결과를 먼저 보여준 뒤, 사용자가 이번 기록 전체를 남길지만 한 번 결정한다. **서랍과 더미 중 어디에 보낼지는 사용자가 고르지 않는다.**

```text
[이 기록 남기기]  [남기지 않고 나가기]
```

- **이 기록 남기기** → 확정된 중심 질문과 이동 경로는 `지나온 생각`에서 볼 수 있고, 대화 중 나왔지만 이번에는 따라가지 않은 Branch는 `남겨둔 질문`에서 볼 수 있다. Branch가 없으면 `남겨둔 질문`에는 아무것도 추가되지 않는다.
- **남기지 않고 나가기** → 이번 기록과 이번 세션에서 새로 생긴 Pile Item을 보관하지 않는다. 기존에 저장된 기록과 Pile Item에는 영향이 없다.

`지나온 생각`과 `남겨둔 질문`은 기록이 갈 두 목적지가 아니다. **같은 세션에서 생긴 서로 다른 종류의 데이터를 보여주는 화면**이다.

따라서 사용자에게 별도 `pile_choice`, `archive_choice`, `save_destination` 같은 선택을 만들지 않는다.

### 화면 노출 규칙

- `지나온 생각`은 사용자가 남기기로 한 완료 세션의 확정 Main Path를 보여준다.
- `남겨둔 질문`은 사용자가 남기기로 한 세션에서 생성된 Pile Item만 보여준다.
- Pile Item은 별도의 저장 선택을 요구하지 않는다.
- `남기지 않고 나가기`를 선택한 세션에서 새로 생긴 Pile Item은 함께 폐기한다.
- Safety Flow에서는 이 보관 선택 자체를 묻지 않는다. Safety 저장 규칙은 10장을 따른다.

### 시각화/기록 공통 규칙

- 대화량을 진행처럼 표현하지 않는다. 턴마다 점을 찍지 않는다.
- `2/4`, `50%` 같은 진행률 표현을 쓰지 않는다. 4는 시스템 상한이지 사용자 목표가 아니다.
- 아무것도 선명해지지 않았으면 화면에 아무것도 추가하지 않는다. 가짜 진행 애니메이션을 넣지 않는다.
- 따라가지 않은 질문은 존재만 알리고 내용은 시야에서 치운다.
- 쌓인 양이 아니라 쌓인 내용을 보여준다. 질문 개수·연속 일수·성장 점수를 만들지 않는다.

## 14. 핵심 요약

> **기본 출력은 질문 하나. 별도의 되받기 문장을 만들지 않고, 사용자 표현을 질문 안에 이어 붙인다.**

> **되받기는 맥락 고정점이지 방향키가 아니다. 방향을 강화하거나 판정 증거를 만들지 않는다.**

> **사용자의 사실뿐 아니라 확신 수준도 임의로 강화하지 않는다.**

> **Close는 상태를 해석하지 않고 관찰로 판정한다 — 새 정보 없음, 표현 반복, 응답 길이 감소.**

> **저장은 세션 전체에 대해 한 번만 선택하고, 저장된 데이터는 성격에 따라 `지나온 생각`과 `남겨둔 질문`에서 보여준다.**

> **애매하면 아무것도 만들지 않는다. False Positive가 가장 큰 오류다.**

## 15. 미결

- Safety Classifier의 구체 프롬프트
- Safety 테스트셋 10개 (미작성) — NONE 4~5, AMBIGUOUS 2~3, HIGH_RISK 2~3
- `lead_in` 필드 필요 여부 — 현재는 만들지 않음. 프롬프트를 돌려보고 어색한 지점이 나오면 추가
