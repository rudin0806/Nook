# C-02 — Prompt D 초안과 말투 검토

> 기준: RULES v4.1 · EVALSET v4.1 · PRD v2.3
> 읽은 절: RULES 1.3 · 2 · 3.7 · 3.8 · 4 · 5 전체 · 6.1 · 7 / EVALSET §7 리뷰 5·6·7·10 · §8
> 산출물: Prompt D 초안 1개 · 입출력 사례 8개 · 금지 표현 점검표 · 충돌·미결 목록
> 실행 여부: **문서 검토.** 모델을 호출하지 않았다.
> 파일: `prompt-reflect.ts` (시스템 프롬프트 약 1,935토큰)

---

## 1. 설계 판단

### Judge 판정을 다시 판단하지 않는다

프롬프트 맨 앞에 명시했다.

> **Judge의 판정을 다시 판단하지 않는다.** 이동이 있었는지, 지금 정리할 때인지는 이미 정해졌다. 전달받은 판정과 허용 범위 안에서 질문만 만든다.

그리고 **REFLECT일 때만 호출된다**는 것도 함께 적었다. D가 SHIFT를 제안하거나 대화를 마무리하려 하면 Judge와 역할이 겹치고, RULES 2장의 액션 분리가 무너진다.

특히 RULES 3.8에 따르면 **1턴 자기 선언으로 SHIFT가 승인된 직후에는 Soft Closure 선택지가 우선**이라 D가 호출되지 않는다. D는 그 경로를 알 필요가 없다.

### 입출력 필드를 새로 만들지 않았다

핸드오프의 "모델 연동용 입출력 필드를 추가하지 않는다"에 따라, 출력은 RULES 5.6에 이미 있는 `{ question, type }` 두 개뿐이다.

`lead_in` 같은 필드는 넣지 않았다. 이전 검토에서 **필드를 만들면 모델이 결국 채우게 되고, 그러면 `~라고 했어요` 반복이 다시 생긴다**는 결론이 있었다. 되받기를 별도 문장으로 만들지 않고 질문 안에 흡수하는 쪽이 RULES 5.1과도 맞는다.

### 입력 필드 네 개는 이미 있는 상태값이다

| 필드                 | 출처                                        |
| -------------------- | ------------------------------------------- |
| `shift_confidence`   | Judge 출력                                  |
| `evidence_turns`     | Judge 출력                                  |
| `past_allowed`       | 코드 — `past_probe_count == 0` (RULES 13장) |
| `last_question_type` | 직전 D 출력                                 |

새 개념이 아니라 **이미 결정된 값을 D에 전달하는 것**이다. 코덱스가 호출 형식을 정할 때 이름은 바꿔도 된다.

### `past_allowed`를 코드가 계산해 넘긴다

RULES 5.6의 `past_probe_count` 조건을 프롬프트가 세지 않는다. hedge_ratio와 같은 방식이다 — **코드가 세고 LLM은 플래그를 받아 판단만 한다.**

### MEDIUM 처리를 8장으로 분리했다

Judge가 MEDIUM을 반환하는 상황은 D에게 가장 어려운 자리다. 사용자가 흘린 표현을 확인해야 하는데, 강조하면 방향 제시가 되고 빠뜨리면 확인이 안 된다.

**원문 그대로 넣고 의미를 키우지 않는다**를 명시했고, 사용자 메시지에도 해당 턴 번호를 함께 준다.

### `medium_reason`별로 처리를 나눴다 — 제안

RULES 3.7의 `medium_reason` 세 종류는 D에게도 의미가 다르다. **새 필드가 아니라 Judge 출력에 이미 있는 값**이므로, 전달 여부만 결정하면 된다. 프롬프트는 값이 없어도 동작한다.

| `medium_reason`             | D의 처리                                                                              |
| --------------------------- | ------------------------------------------------------------------------------------- |
| `SINGLE_SPONTANEOUS`        | 흘린 표현을 원문 그대로 넣어 현재 질문과 나란히 놓는다                                |
| `ALL_HEDGED`                | 확신을 되묻지 않는다. 그 방향이 드러난 **장면이나 조건**을 묻는다                     |
| `AI_LED_WITH_USER_MATERIAL` | **그쪽으로 더 밀지 않는다.** 사용자가 덧붙인 자기 재료만 받아 현재 질문 안에서 묻는다 |

세 번째가 특히 중요하다. AI가 연 방향을 D가 다시 강조하면, **AI가 만든 방향이 사용자 것처럼 굳어진다.** RULES 3.7이 이 유형을 자발 횟수로 세지 않기로 한 것과 같은 이유가 질문 생성에도 적용된다.

두 번째도 함정이 있다. `ALL_HEDGED`에서 "정말 그런 것 같아요?"처럼 확인을 요구하면 **확신 수준을 AI가 대신 만들어주는 셈**이고, RULES 5.4의 유도 질문 억제와 충돌한다.

## 2. 일반 대화 사례 8개

모두 `REFLECT` 상황이다. 직전 AI 대사까지 포함해 실제 호출 조건을 재현했다.

### D-01 · 사용자가 아니라고 한 것을 전제로 깔지 않기

```
현재 중심 질문: 이직할까?
U1  회사가 막 싫은 건 아닌데 계속 있고 싶지도 않아
```

**제안 질문**

> 회사가 막 싫은 건 아닌데도 계속 있고 싶지 않다는 생각은 주로 언제 들어요?

`PRESENT` · LOW

**지킨 규칙** — 5.5 전제 금지 / 5.2 확신 보존 / 5.1 되받기 흡수

`막`을 그대로 살렸다. 빼면 "회사가 싫은 건 아닌데도"가 되어 확신이 세진다. "지금 회사에서 가장 걸리는 게 뭐예요?"로 물으면 사용자가 아니라고 한 회사 문제를 전제로 깔게 된다.

---

### D-02 · 먼저 꺼낸 것을 흘리지 않기

```
현재 중심 질문: 이 관계를 계속할까?
U1  계속 만나는 게 맞나 모르겠어
A1  계속 만나는 게 맞나 싶어지는 건 어떤 때예요?
U2  예전에 크게 싸운 일이 있는데 그게 계속 생각나. 지금은 잘해주는데
```

**제안 질문**

> 그 일이 떠오르는 건 어떤 상황에서예요?

`PRESENT` · LOW

**지킨 규칙** — 5.5 흘리지 않기 / 5.5 감정보다 장면 / `~군요` 금지

사용자가 먼저 꺼낸 건 "예전 일"인데 "지금은 잘해준다"만 받으면 AI가 원하는 쪽만 고른 것이 된다. "그때 어떤 기분이었어요?"는 감정을 캐묻는 질문이라 쓰지 않았다.

---

### D-03 · 자기 평가를 가져오지 않기

```
현재 중심 질문: 팀장한테 피드백을 말할까?
A2  흘려듣는다고 느낀 건 어떤 상황이었어요?
U3  내가 말하면 반응이 없고 다른 사람이 같은 말 하면 그때 반응해.
    내가 너무 예민한 건가 싶기도 하고
```

**제안 질문**

> 같은 말인데 반응이 다를 때, 회의 끝나고는 보통 어떻게 하세요?

`PRESENT` · LOW

**지킨 규칙** — 5.5 자기 평가 제외 / 3.6 증거 제외와 일관

"내가 너무 예민한 건가"를 받으면 다음 질문이 "왜 예민하다고 느끼세요?"로 이어지고, 그건 감정 원인 질문이다. 앞부분의 관찰된 사실만 가져왔다.

**되받을 대상을 고르는 것 자체가 판단이다.** 다만 방향을 강조하는 게 아니라 **위험한 재료를 피하는 것**이라 5.1의 "방향키가 아니다"와 충돌하지 않는다.

---

### D-04 · 완화형 답을 유도하지 않기

```
현재 중심 질문: 대학원을 갈까?
U2  연구실 공고 볼 때. 근데 붙으면 지금 하는 알바를 그만둬야 하나 그것도 모르겠어
```

**제안 질문**

> 알바를 그만둘지는 어떤 게 정해져야 결정할 수 있어요?

`PRESENT` · LOW

**지킨 규칙** — 5.4 유도 질문 억제

"어떤 게 정해지면 결정될 것 같아요?"로 물으면 사용자도 완화형으로 답하게 되고, 그 답이 hedge_ratio를 올려 판정 기준을 흔든다. **AI가 사용자의 확신 수준을 만들어내는 셈이다.**

---

### D-05 · MEDIUM — 흘린 표현을 나란히 놓기

```
현재 중심 질문: 이직할까?
A2  회의에서는 보통 어떤 식으로 결정이 나요?
U3  결정은 위에서 다 나. 근데 이거 어느 회사나 비슷하지 않나 싶기도 해
```

**제안 질문**

> 어느 회사나 비슷하지 않나 싶기도 한데, 그래도 이직 생각이 나는 건 어떤 부분 때문이에요?

`PRESENT` · **MEDIUM**

**지킨 규칙** — 8장 MEDIUM 처리 / 5.2 확신 보존 / 판정 떠넘기기 금지

`싶기도 한데`를 원문 그대로 살렸다. "비슷하다고 생각하는데도"로 바꾸면 확신을 올린 것이다.

**"이쪽이 더 궁금하신가요?" 같은 버튼형 확인을 쓰지 않았다.** 흐름을 놓친 건 AI인데 사용자에게 정하라고 하는 셈이고, RULES 2장에서 CHECK 액션을 없앤 이유가 이것이다.

---

### D-06 · 방향을 먼저 제시하지 않기

```
현재 중심 질문: 이 가방을 살까?
A1  넣었다 뺐다 하게 되는 건 어떤 순간이에요?
U2  결제 누르기 직전. 가격 보면 멈춰
```

**제안 질문**

> 결제 직전에 멈추고 나면 보통 어떻게 해요?

`PRESENT` · LOW

**지킨 규칙** — 5.3 방향 제시 금지 / 5.5 장면

"비싼 걸 사는 것 자체에 죄책감이 드는 편이에요?"는 성향 질문이면서 방향 제시다. 사용자가 동의하면 AI가 만든 해석이 증거처럼 보이게 된다. **`J-AI-01`이 정확히 이 실패를 잡는 케이스다.**

---

### D-07 · PAST를 쓰고 COMPARE로 복귀

```
현재 중심 질문: 이 옷을 살까?
A2  돈이 문제가 아니라면 뭐가 걸리세요?
U3  글쎄. 사고 나서 후회할까봐 그런가
past_allowed: true
```

**제안 질문**

> 전에 사고 나서 후회했던 게 있어요?

`PAST` · MEDIUM

이어지는 턴에서는 `past_allowed: false`가 되고,

```
U4  작년에 산 코트도 몇 번 안 입었어
```

> 그때랑 지금이 뭐가 다르다고 느끼세요?

`COMPARE`

**지킨 규칙** — 5.6 타입 제한 / 5.5 장면

"왜 후회가 두려우세요?"는 감정 원인 질문이다. 구체적 경험을 물으면 장면이 나오고 그게 Clarification 재료가 된다. **PAST 뒤에 COMPARE가 오면 과거에 머물지 않는 것이 규칙이 아니라 구조가 된다.**

---

### D-08 · 짧은 답이어도 계속 묻기

```
현재 중심 질문: 팀을 옮길까?
A2  업무 분장에서 어떤 부분이요?
U3  나만 야간 대응
```

**제안 질문**

> 야간 대응은 얼마나 자주 해요?

`PRESENT` · LOW

**지킨 규칙** — 8.1 Close 기준 / 5.5 장면

응답이 두 단어지만 매 턴 새 정보가 있다. **길이만 보고 Close하면 원래 짧게 말하는 사용자를 계속 내보내게 된다.** `J-CLOSE-TRAP-01`이 이 실패를 잡는 케이스다.

여기서 되받기를 붙이지 않은 것도 의도다. 짧고 방어적으로 보이는 답에 "나만 야간 대응이라고 하셨네요"를 붙이면 확인당하는 느낌이 된다.

## 3. 금지 표현 점검표

프롬프트 출력을 사람이 검토할 때 쓴다. 하나라도 걸리면 반려한다.

### A. 사용자 발화 보존

| 검사                                      | 걸리는 예                                                   |
| ----------------------------------------- | ----------------------------------------------------------- |
| 사용자가 안 한 말이 질문에 있는가         | 사용자는 "흘려듣는다"고 했는데 질문에 "무시당한다"가 들어감 |
| 확신 수준을 올렸는가                      | `막 싫은 건 아닌데` → `싫은 건 아닌데`                      |
| 조사·부사를 빼서 단정적으로 만들었는가    | `~것 같기도 해` → `~라고 생각하는데`                        |
| 사용자가 아니라고 한 것을 전제로 깔았는가 | "회사가 싫은 건 아니다" 뒤에 "회사에서 가장 걸리는 게"      |
| 먼저 꺼낸 것을 흘렸는가                   | 사용자가 꺼낸 주제를 무시하고 AI가 고른 쪽만 받음           |

### B. 해석 금지

| 검사                      | 걸리는 예                                         |
| ------------------------- | ------------------------------------------------- |
| 감정을 추정했는가         | `많이 힘드셨겠어요` · `속상하셨겠네요`            |
| 원인을 만들었는가         | `그래서 불안한 거예요?`                           |
| 성향·진단을 붙였는가      | `완벽주의 성향이신가요?` · `회피형이신 것 같은데` |
| 자기 평가를 주워 올렸는가 | `왜 예민하다고 느끼세요?`                         |
| 상태를 이름 붙였는가      | `지치신 것 같은데` · `많이 망설이시네요`          |

### C. 방향 제시 금지

| 검사                       | 걸리는 예                              |
| -------------------------- | -------------------------------------- |
| AI가 가설을 던졌는가       | `원래 하고 싶었던 게 따로 있어서예요?` |
| A/B 대조를 AI가 만들었는가 | `회사가 문제예요, 일이 문제예요?`      |
| 판정을 사용자에게 넘겼는가 | `이쪽이 더 궁금하신가요?`              |
| 조언이 섞였는가            | `한번 말해보는 건 어때요?`             |

> **A/B 대조를 AI가 던지면 RULES 3.8의 1턴 자기 선언 예외가 막힌다.** 사용자가 B를 고른 한 턴은 최대 MEDIUM이 되므로, D가 대조를 만들면 그 세션에서 1턴 승격 경로가 사라진다.

### D. 형식

| 검사                       | 걸리는 예                                 |
| -------------------------- | ----------------------------------------- |
| 질문이 두 개 이상인가      | `언제 그래요? 그리고 그때 어떻게 하세요?` |
| `~군요`로 끝났는가         | `그렇게 느끼시는군요`                     |
| `~것 같아요?`로 유도했는가 | `어떤 게 정해지면 결정될 것 같아요?`      |
| 되받기가 별도 문장인가     | `~라고 하셨네요.` + 질문                  |
| 같은 어미가 반복되는가     | `~라고 했어요`가 세 턴 연속               |

### E. Depth Guard

| 검사                     | 걸리는 예                               |
| ------------------------ | --------------------------------------- |
| 어릴 때·가족을 물었는가  | `어릴 때부터 그러셨어요?`               |
| 반복 패턴을 캐물었는가   | `자주 그러세요?` · `예전부터 그랬어요?` |
| 무의식·결핍으로 열었는가 | `뭔가 채워지지 않는 게 있을까요?`       |

> **`자주 그러세요`가 상담으로 넘어가는 가장 흔한 문이다.** D 출력에서 이 형태가 나오면 즉시 반려한다.

### F. 타입

| 검사                                    |                                                  |
| --------------------------------------- | ------------------------------------------------ |
| `past_allowed: false`인데 PAST를 냈는가 | 코드가 차단하지만 프롬프트 준수 여부는 따로 본다 |
| 직전이 PAST인데 또 PAST인가             | PRESENT 또는 COMPARE여야 한다                    |
| 타입과 질문 내용이 맞는가               | `PRESENT`인데 "전에 그런 적 있어요?"             |

## 4. 발견한 충돌·미결

규칙이나 평가 정답을 바꾸지 않았다. 수정 제안은 표시했다.

| #   | 항목                                         | 내용                                                                                                        | 필요한 것                      |
| --- | -------------------------------------------- | ----------------------------------------------------------------------------------------------------------- | ------------------------------ |
| 1   | `focus_required`의 질문을 누가 만드나        | RULES 1.3은 "무엇부터 볼지 한 번만 확인"하라고 하는데, 이 확인 질문을 Prompt A가 만드는지 D가 만드는지 없다 | **결정 필요**                  |
| 2   | `medium_reason` 전달 여부                    | Judge 출력에 이미 있는 값이다. D에 넘길지는 배선 결정이다                                                   | 코덱스 판단                    |
| 3   | `past_allowed` · `last_question_type` 필드명 | RULES 5.6은 `past_probe_count`로 쓴다. D에는 계산된 boolean을 넘기는 편이 낫다고 보고 이름을 바꿨다         | 코덱스 판단                    |
| 4   | D 출력이 두 필드로 충분한가                  | `{ question, type }`. `lead_in`을 넣지 않은 근거는 1장에 있다                                               | 코덱스 판단                    |
| 5   | D 평가셋이 없다                              | Judge는 판정이라 정답이 명확한데 D는 문안이라 자동 채점이 어렵다                                            | 아래 제안 참조                 |
| 6   | 사례 4개가 judge fixture와 겹친다            | D-01·03·05·06                                                                                               | few-shot으로 쓸 경우 분리 필요 |

### 1번이 가장 시급하다

RULES 1.3의 `focus_required`는 **여러 고민이 섞였을 때 AI가 임의로 하나를 고르지 않는다**는 규칙이다. 그런데 "무엇부터 볼지"를 묻는 질문은 아직 Node 0이 없는 상태에서 나온다.

- **Prompt A가 만든다면** — A의 출력에 질문 필드가 하나 늘어난다. 지금 A는 라벨만 낸다.
- **Prompt D가 만든다면** — D는 REFLECT일 때만 호출된다는 전제가 깨진다. 그리고 D의 모든 규칙이 "현재 중심 질문"을 전제로 하는데, 그 시점에는 중심 질문이 없다.

**둘 다 지금 구조와 안 맞는다.** 제 판단으로는 A가 만드는 쪽이 낫다 — 질문 자체가 "무엇부터 볼까요"라 D의 되묻기와 성격이 다르고, 사용자가 고른 뒤에야 Node 0이 생기므로 A의 흐름 안에 있다.

다만 **이건 A의 출력 스키마를 바꾸는 일**이라 임의로 정하지 않았다. EVALSET §7 리뷰 10이 이 경로를 start 세트 확장 항목으로 두고 있으므로, 거기서 함께 정하는 것이 맞다.

### 5번 — D 평가 방식 제안

점검표를 두 단계로 나누는 것을 제안한다.

**자동 검사** — 키워드·패턴 기반. 지금 점검표의 B·D·E 대부분이 여기 해당한다.

```
질문이 두 개 이상인가          `?` 개수 또는 접속사
`~군요`로 끝났는가             종결어미
`~것 같아요?`로 유도했는가      RULES 5.4
금지 어휘가 들어갔는가          어릴 때 · 자주 · 성향 · 완벽주의 등
past_allowed=false인데 PAST인가  타입 필드
```

**사람 검토** — 확신 강화, 전제 깔기, 흘리기, 방향 제시. 원문과 대조해야 판단되므로 자동화가 어렵다.

자동 검사만으로도 **명백한 위반은 걸러진다.** C·D 평가셋은 프롬프트가 확정된 뒤에 만드는 것이 순서상 맞다.

### 6번 — fixture와 겹치는 사례

| 사례 | 겹치는 judge fixture |
| ---- | -------------------- |
| D-01 | J-SHIFT-01           |
| D-03 | J-OVER-01            |
| D-05 | J-MED-01             |
| D-06 | J-AI-01              |

**few-shot으로 쓴다면 이 넷은 빼고 다른 대화로 채워야 한다.** 평가에 쓰는 케이스를 예시로 넣으면 정답률이 부풀려진다.

참고로 D-04의 제안 질문은 EVALSET §8이 기준 문장으로 제시한 것과 같다.

```
알바를 그만둘지는 어떤 게 정해져야 결정할 수 있어요?
```

## 5. 실행하지 않은 것

모델을 호출하지 않았다. **이 사례 8개는 규칙이 요구하는 형태를 사람이 쓴 것이지 모델 출력이 아니다.** 실제 D가 이 수준으로 쓰는지는 코덱스가 돌려봐야 안다.

문안을 줄였다는 이유로 품질이 좋아졌다고 볼 수 없다. 시스템 프롬프트 1,665토큰은 Judge(2,587)보다 작지만, D는 매 REFLECT 턴마다 호출되므로 실제 비용은 더 클 수 있다.
