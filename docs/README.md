# Nook Documentation

이 폴더는 Nook의 **제품·판정·진행 상태 문서**를 모아두는 곳입니다.

루트의 `README.md`와 `AGENTS.md`는 진입점이고, 실제 제품 기준은 이 폴더의 문서를 봅니다.

## 문서 지도

| 문서 | 역할 | 언제 읽나 |
|---|---|---|
| `STATUS.md` | 현재 완료 범위, 검증 상태, 다음 작업 | 작업 시작 시 가장 먼저 |
| `PRD.md` | 무엇을 왜 만드는지, MVP 범위와 핵심 UX | 기능·데이터 구조를 결정할 때 |
| `RULES.md` | AI가 어떻게 판정하고 무엇을 말해야 하는지 | Judge, Prompt, Safety, 보관 로직 작업 시 |
| `EVALSET.md` | 판정·Safety 평가 케이스와 기대값 | 프롬프트/eval 구현 및 회귀 검증 시 |

## 권장 읽기 순서

### 일반 개발 작업

1. `../README.md`
2. `STATUS.md`
3. 필요한 경우 `PRD.md`

### AI 엔진·대화 작업

1. `../AGENTS.md`
2. `STATUS.md`
3. `PRD.md`
4. `RULES.md`
5. `EVALSET.md`

### ERD·DB 작업

1. `STATUS.md`
2. `PRD.md`
3. `RULES.md`의 저장·상태·Safety 관련 규칙
4. 사용자와 관계·상태·삭제 규칙을 함께 확정
5. 그 뒤에만 실제 Supabase 스키마 작성

## Source of truth

- **제품 범위와 UX 의도**가 궁금하면 `PRD.md`
- **AI 실행 규칙**이 궁금하면 `RULES.md`
- **현재 무엇이 구현됐는지** 궁금하면 `STATUS.md`
- **규칙이 실제 케이스에서 어떻게 검증되는지** 궁금하면 `EVALSET.md`

같은 내용을 여러 문서에 복사하지 않습니다. 한 규칙이 바뀌면 그 규칙의 기준 문서 한 곳을 수정하고, 다른 문서에는 링크나 짧은 요약만 둡니다.

## 향후 추가 문서

필요해질 때만 추가합니다.

- `ERD.md` — 사용자와 ERD 설계를 확정한 뒤 생성
- `DECISIONS.md` — 단순 문서 수정으로 설명하기 어려운 중요한 설계 결정이 누적될 때만 생성

빈 문서나 미래 계획용 파일을 미리 만들지 않습니다.
